변경 목적

이전 방식은 작업 시작 시 BLACKBOARD.md 전체를 읽는 흐름이었다. 현재 BLACKBOARD.md에는 장기 작업 이력이 누적되어 있었기 때문에, 매 요청마다 전체 상태를 읽으면 실제 작업과 무관한 도메인의 긴 이력까지 컨텍스트에 들어가는 문제가 있었다.

새 방식은 AGENTS.md로 최상위 규칙을 확인하고, MDTREE.md로 요청 도메인을 분류한 뒤, 해당 도메인의 board 파일만 읽도록 바꾼다. 이 변경은 환각 방지 규칙을 유지하면서 토큰 사용량을 줄이기 위한 것이다.

항목 이전 방식 현재 방식 근거
시작 규칙 AGENTS.md와 BLACKBOARD.md를 먼저 읽음. AGENTS.md와 MDTREE.md를 먼저 읽음. AGENTS.md 시작 규칙 섹션.

BLACKBOARD.md 분할 방식

BLACKBOARD.md는 더 이상 상세 작업 로그의 기본 위치가 아니다. 현재 파일은 root index와 cross-domain 상태만 담는 작은 파일로 바뀌었고, 이전 상세 이력은 boards/ARCHIVE/BLACKBOARD_2026-04-30_PRE_HIERARCHY.md에 보존되었다.

분류 파일 역할
Root BLACKBOARD.md 전역 상태, board tree, 현재 migration task block만 유지.
Routing MDTREE.md 요청 도메인별로 읽어야 할 board 파일을 지정.
Archive boards/ARCHIVE/BLACKBOARD_2026-04-30_PRE_HIERARCHY.md 계층화 전 root board 상세 이력 보존.
Monster boards/MON/ 공통 몬스터 규칙과 Eve, Vega, Ariel, Sein, Rin 전용 상태.
Combat boards/COMBAT/ 전투 런타임, 적, 투사체, 상태이상 상태.
Run boards/RUN/ Run 흐름, 보상, 저장/로드 상태.
UI boards/UI/ 공통 UI, DebugScene, MainMenu, RunScene UI 상태.
Data boards/DATA/ CSV, Unity 정적 자산, GameData 관련 상태.
Ops boards/OPS/ Reviewer, Codex CLI, Unity MCP, 자동화 규칙.
Report boards/REPORT/REPORT_BLACKBOARD.md HTML 보고서와 문서화 작업 상태.

작업 방법 변경

단계 현재 절차 토큰 최적화 효과
1. 규칙 확인 AGENTS.md를 읽어 role, evidence, Reviewer, Play Mode 규칙을 확인. 항상 필요한 최상위 규칙만 고정 비용으로 사용.
2. 라우팅 MDTREE.md를 읽고 사용자 요청을 MON, COMBAT, RUN, UI, DATA, OPS, REPORT 등으로 분류. 불필요한 도메인 board를 읽지 않음.
3. 관련 board 읽기 요청 도메인에 해당하는 board 파일만 읽음. 전역 질문이면 BLACKBOARD.md도 읽음. 상세 이력이 많은 root board 전체 로드를 피함.
4. 구현 또는 설계 Designer/Code Builder/Code Reviewer role 규칙에 맞춰 실제 파일과 명령 출력 근거로 작업. 기존 환각 방지 규칙은 유지.
5. 상태 기록 변경된 사실이 걸친 모든 관련 board를 같은 작업 안에서 갱신. 상태가 흩어져도 각 도메인별로 다음 작업 시작 비용을 줄임.

검증한 실제 상태

  • AGENTS.md는 AGENTS.md + MDTREE.md 우선 읽기와 board routing 규칙을 포함한다.
  • MDTREE.md는 MON, COMBAT, RUN, UI, DATA, OPS, REPORT 라우팅을 정의한다.
  • BLACKBOARD.md는 root persistent-state index로 축소되었다.
  • boards/ARCHIVE/BLACKBOARD_2026-04-30_PRE_HIERARCHY.md가 존재한다.
  • boards/ 아래에는 MON, COMBAT, RUN, UI, DATA, OPS, REPORT, ARCHIVE 계층 파일들이 존재한다.
  • git status --short 기준 현재 uncommitted 변경에는 이 board migration 관련 파일 외에 Pakuri/Assets/Scenes/DebugScene.unity 등 다른 작업 변경도 남아 있다.

주의: 이 보고서는 토큰 최적화용 문서/board routing 변경을 설명한다. Unity Play Mode gameplay 검증이나 외부 Code Reviewer 실행 결과를 새로 주장하지 않는다.

결론

현재 구조는 큰 root board를 매번 읽는 방식에서, 작은 routing index와 도메인별 board를 조합하는 방식으로 바뀌었다. 이로 인해 요청 범위가 명확한 작업은 필요한 board만 읽고 시작할 수 있다. 동시에 AGENTS.md의 최상위 근거 규칙, role 규칙, Reviewer 허락 규칙, Unity Play Mode 제한 규칙은 유지된다.
