Combat V2 Foundation Architecture

작성일: 2026-05-13 / 역할: Designer / 범위: 새 전투 씬과 새 전투 런타임의 기초 구조 설계

결론: 기존 Run UI Flow, RunSession, CSV/Data 로딩 방식은 유지하고, 전투만 CombatV2 계층과 새 전투 씬에서 병렬 구축한다.

핵심 결정: 전투 계산 모델은 프리팹/애니메이션과 분리한다. 유닛 프리팹에는 얇은 MonsterUnitActor 또는 EnemyUnitActor가 붙고, 실제 전투 상태는 순수 런타임 모델이 소유한다.

1. 근거로 확인한 현재 구조

확인 항목 근거 Combat V2 설계 반영
Run 시작 계약 RunSceneBootstrap.BeginCombat(...)가 MonsterDefinition, RunSession, GameDataCatalog를 CombatRuntimeController.BeginConfiguredDay(...)로 전달한다. 새 전투도 같은 입력 계약을 받는 CombatV2Controller.BeginConfiguredDay(...)를 제공한다.
몬스터 데이터 MonsterDefinition은 BaseStats, Defenses, MaxHealth, PowerStat, BaseDamage, 탄창, 재장전, 투사체 값을 가진다. 몬스터 프리팹은 데이터를 중복 저장하지 않고 MonsterDefinition에서 런타임 모델을 구성한다.
적 데이터 EnemyDefinition은 Stats, Defenses, AttackType, StageOneSkill, 액티브 스킬 튜닝 값을 가진다. 적 프리팹도 EnemyDefinition 기반으로 구성하며, 스폰 매니저가 정의와 프리팹을 결합한다.
공통 스탯 CombatStatBlock에는 최대 HP, 공격력, 주문력, 이동속도, 치명 확률, 치명 피해, 치명 저항이 있다. AttributeDefenseSet에는 물리/화염/전격/빙결/어둠/신성 방어가 있다. UnitRuntimeModel의 기본 스탯/방어 데이터로 직접 채택한다.
현재 적 상태 현재 EnemyRuntime은 HP, 쉴드, 이동/공격 버프, 쇼크, 칠, 빙결, 취약, 슬로우, 성흔, Rin/Sein/Vega 전용 상태를 함께 가진 private nested class이다. V2에서는 공통 상태는 StatusEffectController와 ShieldController로 이동하고, 캐릭터 전용 상태는 전용 state bucket으로 분리한다.
스킬 데이터 SkillDefinition에는 RuntimeKind, SkillEffectPrefab, 피해 계수, 범위, 반경, 쿨다운, 탄창, 상태 ID, 강화 선택 배열이 있다. 스킬은 데이터/실행기/시각 프리팹을 분리한다. 프리팹은 로직 소유자가 아니라 표현 리소스다.

2. 사용자 결정 반영

질문 결정
전투 상태와 프리팹 결합 방식 순수 런타임 모델을 만들고 프리팹에는 얇은 Actor/View만 둔다.
개별 유닛 클래스 Eve_Unit, Stage1_Warrior 같은 개별 C# 클래스는 고유 행동이 있을 때만 둔다. 식별은 데이터로 처리한다.
스킬 관리 방식 하드코딩을 줄이고 수정/관리가 자유롭도록 데이터 기반 구조를 우선한다.
현현 유닛 1P와 2P-5P는 같은 MonsterUnitActor를 사용한다. 스킬 강화도 같은 유닛 상태를 조회한다.
자동 공격 1P와 현현 유닛 모두 자동 공격 기능을 가진다. 기본은 켜짐이며 유닛별로 끌 수 있어야 한다.
UI 연결 지금은 새 UI/기존 UI 연결을 구현하지 않는다. 새 전투가 먼저 나온 뒤 연결한다.
강화 저장 스킬 자체를 변형하지 않고 유닛 상태에 learned choices를 저장한 뒤 스킬 실행 시 조회한다.

4. UnitRuntimeModel

Base_Unit라는 이름의 MonoBehaviour 루트를 바로 만들기보다, 전투 계산을 담당하는 UnitRuntimeModel을 최상위 모델로 둔다. Unity 프리팹은 이 모델을 표시하고 입력/애니메이션을 전달하는 Actor다.

영역 필드 / 책임
식별 UnitRuntimeId, DefinitionId, DisplayName, Team, UnitKind, MonsterId 또는 EnemyId
생명력 MaxHealth, CurrentHealth, IsAlive, IsTargetable
쉴드 ShieldController가 쉴드 값, 지속시간, 적용 프레임, 흡수/반사/폭발 옵션을 소유한다.
스탯 CombatStatBlock 기반 최대 HP, 공격력, 주문력, 이동속도, 치명 확률, 치명 피해, 치명 저항
방어 AttributeDefenseSet 기반 물리, 화염, 전격, 빙결, 어둠, 신성 방어
행동 ActionSpeedMultiplier, AutoAttackEnabled, AutoSkillEnabled, 기본 공격 타이머
스킬 SkillRuntimeInstance 리스트, learned active/passive, learned choices 조회 포인터
상태 StatusEffectController가 shock, chill, freeze, slow, vulnerable, silence, mark, holy exposure, 방어 감소, 피해 증가 등을 소유한다.
전용 상태 Rin, Sein, Vega, Ariel 같은 캐릭터 전용 타이머는 CharacterStateBucket 또는 캐릭터별 state object로 분리한다.
주의: Eve_Unit, Sein_Unit, Stage1_Warrior 같은 클래스를 식별만 위해 만들면 클래스 수만 늘어난다. 식별은 데이터로 처리하고, 특수한 AI/스킬/애니메이션 훅이 필요할 때만 전용 컴포넌트를 붙인다.

5. Actor / View 계층

컴포넌트 책임 소유하지 말아야 할 것
MonsterUnitActor 1P와 현현 2P-5P가 공통으로 쓰는 프리팹 Actor. 위치, Renderer, Collider, AnimationBridge, StatusPresenter를 바인딩한다. 피해 공식, 강화 판정, 스킬 쿨다운 계산
EnemyUnitActor 적 프리팹 Actor. SpawnManager가 생성하고 런타임 모델과 바인딩한다. 스폰 정책, 타겟 우선순위, 피해 공식
UnitAnimationBridge 런타임 상태를 Animator 파라미터로 변환한다. Idle, Move, Attack, Cast, Hit, Dead 같은 상태를 표현한다. 전투 상태를 직접 변경하는 권한
UnitStatusPresenter HP bar, Shield bar, 상태 텍스트, 이름표 갱신 HP/Shield 계산

6. 스킬 구조

스킬은 세 조각으로 분리한다.

  1. SkillDefinition: CSV/SO에서 온 데이터. ID, 슬롯, 타입, 계수, 쿨다운, 탄창, 반경, 프리팹, 강화 선택을 가진다.
  2. SkillExecutor: 실제 판정과 효과 적용 로직. 가능한 한 타입별 공통 executor를 재사용한다.
  3. SkillEffectPrefab: 시각 효과, 투사체 외형, 장판 외형, 소환체 외형. 로직의 소유자가 아니다.

스킬 타입 제안

타입 용도 현재 구조 근거
MagazineProjectile 탄창/재장전 기반 기본 공격 또는 연사형 투사체 기존 SkillRuntimeKind.MagazineProjectile, CombatSkillRuntime의 탄창/재장전 필드
CooldownProjectile 쿨다운마다 단발/다중 투사체 발사 기존 SkillRuntimeKind.CooldownProjectile
LineAttack 광선, 직선 참격, 레이저 기존 CombatEffectFactory.CreateLine(...), SkillRuntimeKind.LineAttack
AreaAttack 즉발 원형/사각형 범위 피해 기존 SkillRuntimeKind.AreaAttack
Field 지속 장판, 반복 tick 피해, 상태 누적 기존 SkillEffectRuntime의 지속시간, tick interval, radius
Summon / Drone 드론, 소환체, 독립 발사체 생성기 기존 DroneRuntime, manifested drone 경로
Buff 행동 속도, 공격력, 피해량, 방어력 변화 기존 SkillRuntimeKind.Buff, enemy/unit buff timer들
Shield 쉴드 부여, 흡수, 반사, 폭발 기존 SkillRuntimeKind.Shield, Ariel/Eve shield 구현
Heal 아군 회복 또는 적 사제 회복 기존 SkillRuntimeKind.Heal, StageOneEnemySkillKind.Heal
Mark 표식, 이름 각인, 성흔 같은 누적 상태 기존 SkillRuntimeKind.Mark, Vega name mark, Ariel holy exposure
Execute 조건부 처형, 마무리 피해 기존 SkillRuntimeKind.Execute
Passive 항상 적용되거나 특정 이벤트에서 발동하는 패시브 기존 PassiveDefinition, SkillRuntimeKind.Passive
Chain / Branch 분기 투사체, 연쇄 피해, 사망 시 전이 기존 ProjectileRuntime.BranchChance, BranchRadius, Vega mark transfer

7. 강화 / learned choices 모델

강화는 스킬 정의를 직접 변경하지 않는다. 현재 RunSession.RunMonsterState가 유닛별 learned actives/passives와 chosen rewards를 저장하므로, V2도 이 흐름을 유지한다.

  • UnitRuntimeModel은 자신의 RunMonsterState 참조 또는 읽기 전용 스냅샷을 가진다.
  • SkillExecutionContext는 HasLearnedActive, HasLearnedPassive, HasChoice 같은 조회 API를 제공한다.
  • 1P와 현현 유닛은 같은 조회 방식으로 강화 효과를 받는다.
  • Offering으로 추가된 스킬도 유닛 상태에 기록되고, 스킬 실행 시 해당 유닛의 상태에서 조회한다.

8. 자동 공격 정책

항목 정책
기본값 1P와 현현 유닛 모두 AutoAttackEnabled = true로 시작한다.
토글 유닛별로 자동 공격을 켜고 끌 수 있다. UI 연결은 나중 단계에서 한다.
수동/자동 공존 1P는 자동 공격을 켜도 나중에 수동 스킬 입력을 받을 수 있게 한다. 자동 공격은 기본 A/기본 공격 cadence를 담당한다.
현현 유닛 현현 유닛도 같은 MonsterUnitActor와 같은 스킬 실행기를 쓰며, 기본 행동은 자동 공격이다.

9. 전투 실행 순서

  1. CombatV2Controller.BeginConfiguredDay(...)가 RunSession과 데이터 카탈로그를 받는다.
  2. CombatV2Context가 전투 하루치 설정, 난이도, 스테이지, 보상 결과 콜백을 구성한다.
  3. UnitFactory가 1P와 현현 유닛을 같은 MonsterUnitActor 프리팹으로 생성/바인딩한다.
  4. SpawnManagerV2가 적 정의와 스폰 규칙에 따라 EnemyUnitActor를 생성한다.
  5. 매 tick마다 상태효과, 스킬 쿨다운, 자동 공격, 소환체, 투사체, 장판, 적 AI, 승패 판정을 순서대로 실행한다.
  6. 결과는 UI가 아니라 CombatResultModel로 먼저 반환한다.

10. 구현하지 않을 것

  • 이 단계에서는 기존 RunCombatUiController 연결을 구현하지 않는다.
  • 기존 CombatRuntimeController를 삭제하지 않는다.
  • 모든 캐릭터 스킬을 한 번에 V2로 이식하지 않는다.
  • 스킬 프리팹에 피해 계산, 타겟 탐색, 쿨다운 소유권을 넣지 않는다.
  • 식별 목적만으로 유닛별 C# 클래스를 대량 생성하지 않는다.

11. 권장 구현 순서

  1. V2 계약 정의: CombatV2Controller.BeginConfiguredDay(...), CombatResultModel, UnitRuntimeModel 골격만 만든다.
  2. 데이터 연결: MonsterDefinition, EnemyDefinition, RunSession.RunMonsterState를 읽어 런타임 모델을 생성한다.
  3. 단일 전투 세로 조각: 1P 몬스터 1명과 적 1종을 새 씬에서 스폰하고 자동 공격만 구현한다.
  4. 공통 피해/쉴드/상태: HP, 쉴드, 피해 적용, 방어 계산, 기본 상태효과 컨트롤러를 붙인다.
  5. 스킬 executor: projectile, line, area, field, summon/drone 순서로 타입별 executor를 추가한다.
  6. 현현 유닛: 같은 MonsterUnitActor로 2P-5P를 추가하고 자동 공격 토글을 공유한다.
  7. 강화 조회: learned choices를 유닛 상태에서 조회해 1P와 현현 유닛이 같은 강화 결과를 받게 한다.
  8. UI 연결: 새 전투가 독립적으로 검증된 후에 기존 UI 어댑터 또는 RunCombatUiControllerV2를 설계한다.

12. 수용 기준

  • 새 전투 V2는 기존 CSV/Data 로딩 코드를 변경하지 않고 MonsterDefinition, EnemyDefinition, SkillDefinition을 읽는다.
  • 1P와 현현 몬스터가 같은 MonsterUnitActor 프리팹과 같은 스킬 실행 경로를 사용한다.
  • 자동 공격은 1P와 현현 유닛 모두 기본 활성화이며 유닛별로 끌 수 있다.
  • 스킬 강화는 유닛별 learned state를 조회하며 스킬 데이터 자산을 런타임에 변형하지 않는다.
  • 투사체, 광선, 장판, 소환/드론, 버프, 쉴드, 힐, 표식, 처형, 패시브 계열은 타입별 executor로 분리된다.
  • 프리팹은 표시와 충돌/애니메이션 연결만 담당하고 전투 공식의 소유자가 되지 않는다.
