DebugScene UI Canvas 제작 방식 회고

작성일: 2026-04-30 / 근거: BLACKBOARD.md 최근 작업 로그, 현재 DebugSceneController.cs, 현재 DebugScene.unity

초기 DebugSceneController가 실행 중 uGUI 패널과 토글을 만드는 방식이었다.
전환 사용자 지적 후 씬에 편집 가능한 UI 오브젝트를 저장하고 코드가 바인딩하는 방식으로 바뀌었다.
현재 Awake()에서 EnsureCanvasShell() 뒤 BindSceneUi()를 호출한다.
남은 검증 Play Mode gameplay 검증은 AGENTS.md 규칙상 사용자가 수행한다.

1. 처음 만든 방식

최초 DebugScene UI는 코드가 런타임에 UI를 조립하는 방향이었다. BLACKBOARD.md 작업 로그에는 DebugSceneController.cs가 DebugScene 전용 uGUI 패널을 만들고, 5개 몬스터 버튼, A-J 스킬 토글, 강화/마스터 토글, RunSession 재시작 흐름을 제공하도록 추가되었다고 기록되어 있다.

이 방식의 장점은 코드만으로 UI를 빠르게 만들 수 있다는 점이었다. 하지만 사용자가 요구한 것은 “실행 중 생성되는 UI”가 아니라 “씬에서 직접 보고 수정할 수 있는 UI”였고, 이후 문제들도 대부분 런타임 생성 UI의 레이아웃, 활성화 순서, 시각 리소스, 씬 저장 상태와 관련되어 발생했다.

2. 사용자 지적과 수정 흐름

순서 사용자 지적 또는 Reviewer 지적 원인 판단 해결 방식
1 DebugScene 시작 시 적이 바로 생성되지 않고, 몬스터/스킬을 고른 뒤 Start로 시작해야 한다. 초기 흐름은 UI 설정과 전투 시작 책임이 분리되지 않았다. CombatRuntimeController.ApplyDebugSelection(...)을 추가해 선택 상태 적용과 BeginConfiguredDay(...) 전투 시작을 분리했다는 작업 로그가 남아 있다.
2 SkillDebugPanel 스킬 리스트가 보이지 않는다. 패널 활성화 순서와 ScrollRect content 높이가 불안정했다. OpenSkillWindow()에서 패널을 먼저 활성화하고, 토글 생성 후 content 높이를 갱신하도록 수정했다는 작업 로그가 있다.
3 그래도 스킬 리스트가 보이지 않으므로, 게임 실행 중 생성 방식 대신 씬에서 편집 가능한 UI로 만들어야 한다. 런타임 생성 UI는 사용자가 씬에서 위치, 크기, 자식 구조를 직접 확인하고 조정하기 어렵다. 현재 코드는 BuildUi() 호출이 아니라 BindSceneUi()를 호출하고, 씬의 DebugSetupPanel, SkillDebugPanel, EnhancementModal을 직접 찾는다.
4 Reviewer가 DebugSetupPanel과 setup controls가 씬에 없다고 실패 판정했다. 코드는 씬 오브젝트를 요구하지만 씬 저장 상태가 그 요구와 맞지 않았다. 씬에 DebugSetupPanel/Title, Status, CombatText, MonsterButtons, SkillWindowButton, StartButton을 복구했다는 로그가 남아 있다.
5 Reviewer가 DebugSceneController 루트 scale이 {0,0,0}이라 UI가 접힐 수 있다고 지적했다. 부모 scale이 0이면 자식 UI가 있어도 시각적으로 사라지고 입력도 불안정해진다. 현재 EnsureCanvasShell()은 scale이 정확히 Vector3.zero일 때만 Vector3.one으로 복구해, 사용자가 편집한 non-zero scale은 보존한다.
6 토글은 클릭되지만 스킬 설명과 체크박스가 보이지 않는다. 토글의 Label, Background, Checkmark, Toggle.graphic 연결이 실제 씬 오브젝트에서 안정적으로 보장되지 않았다. ConfigureToggleVisuals(...)가 각 토글 바인딩 시 Background, Checkmark, Label을 재구성하고 toggle.targetGraphic, toggle.graphic을 명시적으로 연결한다.
7 Failed to find UI/Skin/UISprite.psd 오류가 발생했다. Unity 내장 UI skin 경로에 의존한 sprite 로딩이 현재 Unity 환경에서 실패했다. 프로젝트 소유 리소스 Assets/Resources/DebugUiSolid.png를 만들고, 현재 코드는 Resources.Load<Sprite>("DebugUiSolid")만 사용한다.
8 EnhancementModal 자식들도 같은 방식으로 보이고 편집 가능해야 한다. 스킬 토글만 정규화하면 강화 선택 UI의 Label/Checkmark 문제가 남을 수 있다. 작업 로그 기준으로 EnhancementModal의 Title, Summary, CloseButton, ChoiceScroll/Viewport/Content, Choice_01-Choice_08을 씬 오브젝트로 재생성했다.

3. 현재 구조

현재 DebugSceneController.Awake()는 DisableRunSceneControllers(), ResolveReferences(), EnsureCanvasShell(), EnsureEventSystem(), BindSceneUi() 순서로 실행된다. 이 구조는 Canvas shell과 EventSystem 같은 실행 필수 요소는 코드로 보장하되, 실제 패널과 토글 슬롯은 씬에 저장된 오브젝트를 바인딩한다.

구성요소 현재 근거 역할
DebugSetupPanel DebugSceneController.cs:162-181, DebugScene.unity:1892 몬스터 선택, 스킬 창 열기, Start 버튼, 상태/전투 텍스트 표시.
SkillDebugPanel DebugSceneController.cs:182-185, DebugScene.unity:4753 A-E active, F-J passive 스킬 토글 슬롯을 씬 오브젝트로 보유.
EnhancementModal DebugSceneController.cs:188-193, DebugScene.unity:429 강화/마스터 선택지를 별도 모달로 표시하고 닫을 수 있게 한다.
Active_A-Passive_J DebugSceneController.cs:714-727, DebugScene.unity:7954, DebugScene.unity:6547 스킬 토글 슬롯. 없으면 코드가 오류 로그를 낸다.
Choice_01-Choice_08 DebugSceneController.cs:765-781, DebugScene.unity:9026, DebugScene.unity:2092 강화 선택지 토글 슬롯. 모달이 열릴 때 비어 있는 슬롯부터 사용한다.
DebugUiSolid.png DebugSceneController.cs:111, Assets/Resources/DebugUiSolid.png 체크박스 배경과 체크 표시용 프로젝트 소유 Sprite 리소스.

4. 최종 해결의 핵심

  • 편집 가능성: UI의 주요 패널과 토글 슬롯을 씬에 저장해 Unity Editor에서 직접 위치와 크기를 조정할 수 있게 했다.
  • 코드 책임 축소: 코드는 씬 오브젝트를 새로 만드는 주체가 아니라, 존재 여부를 검증하고 이벤트/텍스트/토글 상태를 바인딩하는 주체가 되었다.
  • 시각 안정성: ConfigureToggleVisuals(...)가 Label, Background, Checkmark를 매번 명시적으로 정규화한다.
  • 리소스 안정성: Unity 내장 UI skin sprite 대신 DebugUiSolid.png를 사용해 Unity 버전/환경별 내장 리소스 경로 실패를 피했다.
  • 사용자 편집 보존: root scale은 0일 때만 복구하고, non-zero scale/position은 코드가 덮어쓰지 않는 방향으로 정리했다.

5. 근거 요약

이 문서는 추측이 아니라 다음 실제 확인 결과에 기반한다. Select-String 확인 결과 현재 DebugSceneController.cs에는 BindSceneUi, EnsureCanvasShell, ConfigureToggleVisuals, DebugUiSolid 사용 지점이 존재한다. DebugScene.unity에는 DebugSceneController, DebugSetupPanel, SkillDebugPanel, EnhancementModal, Active_A, Passive_J, Choice_01, Choice_08 이름의 씬 오브젝트가 존재한다. Assets/Resources에는 DebugUiSolid.png와 meta 파일이 존재한다.

6. 이후 작업 시 주의점

  • 씬 UI를 다시 수정할 때는 코드에서 생성하는 방식으로 되돌리지 말고, 씬 오브젝트 경로와 BindSceneUi() 요구 경로를 함께 맞춰야 한다.
  • 새 토글 슬롯을 추가할 때는 씬에 오브젝트를 먼저 만들고, 코드의 슬롯 바인딩 목록을 실제 이름과 일치시켜야 한다.
  • 스프라이트는 Unity 내장 UI/Skin 경로에 의존하지 말고 프로젝트 리소스 또는 명시적 asset reference를 사용해야 한다.
  • Play Mode에서 실제 클릭/표시 검증은 AGENTS.md 규칙에 따라 사용자가 수행하고, Codex는 빌드/컴파일/콘솔/에디터 상태 확인까지만 근거로 남긴다.
