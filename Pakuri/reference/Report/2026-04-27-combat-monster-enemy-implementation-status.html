Combat / Monster / Enemy 구현 현황 비교

기준 문서 Pakuri/reference/Report/combat-monster-enemy-implementation-plan.html와 2026-04-27 현재 실제 코드 및 자산을 비교한 구현 현황 보고서다. 플레이 모드 동작 검증은 사용자가 수행하는 범위이므로, 이 문서는 파일 내용과 빌드 결과까지만 근거로 삼는다.

작성일: 2026-04-27 Role: Designer 근거: 실제 C# 파일, 생성 자산, BLACKBOARD.md, dotnet build 출력

요약

구현됨 전투 데이터 모델, 속성별 방어력 계산, Stage 1 적 데이터 자산, 선택 Monster 기본 데이터 연결, 적 우선 타겟/투사체/HP 표시가 코드에 존재한다.
부분 구현 Monster A~E/F~J 스킬 데이터는 들어갔지만, 모든 스킬의 고유 실행기와 선택지 풀 완성은 아직 제한적이다.
미완료 전체 상태이상 시스템, 전체 보상 선택 규칙, 모든 Monster 스킬의 런타임 효과, 플레이 모드 검증은 완료 근거가 없다.

dotnet build Pakuri\Assembly-CSharp.csproj --no-restore는 오류 0개로 통과했다. 남은 경고는 기존 Unity/MCPForUnity 참조의 System.Net.Http, System.IO.Compression 버전 충돌 경고 2개다.

계획 대비 구현 매트릭스

계획 항목 현재 상태 실제 구현 근거 남은 작업
공통 전투 모델 구현됨 CombatStatModels.cs에 AttributeDefenseSet, CombatStatBlock, DefenseBreakdown가 존재한다. 방어 속성은 Physical, Fire, Lightning, Ice, Darkness, Holy로 구성된다. 상태이상과 버프/디버프를 별도 런타임 모델로 완전히 분리하는 작업은 남아 있다.
속성별 방어력과 데미지 계산 구현됨 DamageCalculator.Resolve(... DamageAttribute, AttributeDefenseSet ...)가 속성별 방어력, 고정 방어 증감, 퍼센트 방어 증가, 퍼센트 방어 감소, 치명타 저항, 치명타 피해 증가, 최종 피해 배율을 계산한다. DamageResult.FormulaLog도 추가되어 계산 로그를 남길 수 있다. 문서에 있는 모든 특수 상태이상 보정이 계산기에 연결된 것은 아니다.
Stage 1 적 데이터 구현됨 EnemyDefinition.cs가 적 ScriptableObject 타입을 정의하고, PakuriGameDataSeeder.cs의 CreateOrUpdateStageOneEnemies()가 검사, 방패병, 궁수, 도적, 사제, 수호대장, 공격대장, 용사 카린 8개를 생성한다. 실제 Pakuri/Assets/Data/GameData/Enemies 아래에 8개 .asset 파일이 존재한다. Stage 2 이후 적 데이터는 이 보고서 기준 구현 범위 밖이다.
GameDataCatalog에 Stage 1 적 연결 구현됨 GameDataCatalog.cs에 StageOneEnemies 배열과 FindStageOneEnemy 흐름이 존재한다. PakuriGameDataSeeder.cs는 catalog의 StageOneEnemies에 생성된 적 배열을 대입한다. CSV 런타임 로더는 구현하지 않았고, 현재 방향은 Unity 자산 기반이다.
Monster 기본 전투 데이터 구현됨 MonsterDefinition.cs에 PrimaryAttribute, BaseStats, Defenses, ActiveSkills, PassiveSkills가 추가됐다. 기존 MaxHealth, PowerStat, BaseDamage 등 프로토타입 필드도 유지된다. 레거시 프로토타입 필드와 신규 BaseStats 필드의 장기 정리는 아직 남아 있다.
Monster A~E/F~J 스킬 데이터 부분 구현 SkillDefinition.cs에 SkillDefinition, PassiveDefinition, SkillImplementationState가 존재하고, PakuriGameDataSeeder.cs가 Monster별 BuildMonsterActiveSkills, BuildMonsterPassives를 통해 배열을 채운다. 데이터는 들어갔지만, A~E/F~J 각각의 고유 런타임 효과가 모두 실행되는 구조라고 볼 근거는 아직 없다.
선택 Monster 전투 연결 구현됨 EveVerticalSliceController.BeginConfiguredDay(MonsterDefinition, RunSession, GameDataCatalog)가 catalog를 받는다. ConfigureMonster 흐름은 monster.PrimaryAttribute, monster.Defenses.Clone()을 선택 Monster 런타임 값으로 복사한다. 선택 Monster별 완전한 스킬 실행 분기는 아직 제한적이다.
Stage 1 적 전투 연결 구현됨 EveVerticalSliceController.ResolveStageOneEnemyPool()가 catalog의 StageOneEnemies를 읽고, 없는 경우 fallbackStageOneEnemyCache를 통해 fallback 적을 만든다. SpawnEnemy()는 EnemyDefinition의 스탯, 방어력, 액티브/패시브 정보를 런타임 적에 복사한다. Fallback 경로는 안전망이며, 정상 경로는 catalog 자산을 쓰는 방향이다.
적 스킬 및 패시브 최소 구현 부분 구현 TryUseStageOneEnemySkill()에 ShieldUp, Heal, GuardianFlag, ChargeCommand, 기본 공격/투사체 분기가 있다. 궁수/도적 치명타 패시브, 수호대장 피해 감소, 공격대장/용사 카린 물리 피해 보정도 런타임 필드에 반영된다. 모든 기획 문서의 상태이상/특수 효과까지 일반화한 스킬 시스템은 아직 아니다.
적이 Monster를 먼저 공격 구현됨 GetEnemyPriorityTarget()는 Monster HP가 남아 있으면 eveAnchor를 반환하고, 이후 Nexus로 fallback한다. ApplyEnemyDamageToPriorityTarget()도 Monster HP를 먼저 감소시킨다. 플레이 모드에서 실제 체감 검증은 사용자 확인 범위다.
적 투사체 기반 원거리 피해 구현됨 FireEnemyProjectile()가 적 투사체를 만들고, UpdateProjectiles()는 enemy projectile 분기를 통해 TryHitEnemyProjectileTarget()에서 충돌 시 피해를 적용한다. 투사체 시각 품질은 기본 1x1 sprite 기반이므로 후속 아트 단계에서 개선 가능하다.
HP 텍스트 및 HP 바 표시 구현됨 CreateEnemyLabel(), CreateHpBar(), UpdateHpBarFill()가 있고, 선택 Monster는 EnsureSelectedMonsterStatusVisuals()와 UpdateSelectedMonsterStatusVisuals()로 이름/HP/바를 갱신한다. 실제 화면 가독성은 Play Mode 검증이 필요하다.
전투 데미지 로그 구현됨 EveVerticalSliceController.UpdateProjectiles()에서 Monster 공격이 적중하면 Debug.Log("[CombatDamage] ...")로 FormulaLog, 적용 피해, 보호막 잔량, HP 잔량을 출력한다. 적이 Monster/Nexus를 때리는 경우까지 동일한 로그 체계로 확장할지는 후속 판단 대상이다.

남은 범위

  • Monster별 A~E 액티브, F~J 패시브의 모든 고유 런타임 효과 구현.
  • 기획 문서에 있는 상태이상 전체를 범용 시스템으로 모델링하고 스킬 실행기에 연결.
  • 보상 선택 풀 규칙과 최대 액티브/패시브 습득 제한을 전체 Monster 데이터에 대해 검증.
  • EveVerticalSliceController가 전투, 스폰, UI, 데미지 표시를 모두 담고 있어 후속 분리 필요.
  • Unity Play Mode에서 적 스폰, 투사체 충돌, HP 바 갱신, Monster 우선 타겟, Stage 1 일차별 보스 등 실제 동작 확인.
