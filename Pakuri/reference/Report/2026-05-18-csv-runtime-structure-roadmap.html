Working Roadmap

CSV Runtime Structure Review And Cleanup Roadmap

이 문서는 현재 NewRunScene 기준 CSV 로드 구조, 실제 적용 경로, 과도기 상태의 문제, 하드코딩 지점, 정리 우선순위를 작업용 로드맵으로 정리한 것이다.

모든 판단은 2026-05-18 기준 실제 코드, 씬 YAML, CSV 파일, 그리고 현재 남아 있는 데이터 자산 참조를 근거로 한다.

1. 결론

현재 구조는 CSV 중심이지만 단일 CSV 원본 구조는 아니다.

  • 몬스터/적 런타임 카탈로그는 주로 Assets/CSVdata/source/*.csv와 Assets/CSVdata/EnemySkillData.csv를 읽는다.
  • 스테이지는 StageDay.csv, StageEncounter.csv, StageReward.csv를 직접 읽는다.
  • 스킬 강화 modifier는 SkillChoiceModifierData.csv를 별도로 읽는다.
  • 반면 MonsterStat.csv, SkillData.csv, EnemyStat.csv, SkillChoiceData.csv는 현재 Scripts2 런타임 직접 원본으로 확인되지 않았다.
  • 추가로 NewRunScene에는 아직 Legacy/Data/GameData/GameDataCatalog.asset fallback 참조가 남아 있다.

2. 현재 실제 원본 계층

영역 현재 실제 원본 현재 분류 근거
몬스터 스탯/스킬/보상 Assets/CSVdata/source/monsters.csv, monster_skills.csv, monster_reward_choices.csv, monster_skill_choices.csv 유지 대상 PakuriCsvRuntimeData가 source catalog를 구성하고 runtime catalog를 빌드한다.
적 스탯/스킬 Assets/CSVdata/source/stage_one_enemies.csv + Assets/CSVdata/EnemySkillData.csv 유지 대상 적 row와 적 skill row를 따로 읽은 뒤 ApplyEnemySkillRow(...)로 합친다.
스테이지 진행 StageDay.csv, StageEncounter.csv, StageReward.csv 유지 대상 NewRunStageManager가 씬 직렬화된 TextAsset으로 직접 읽는다.
스킬 강화 세부 수치 SkillChoiceModifierData.csv 유지 대상 InGameCombatManager.skillChoiceModifierCsv가 parser를 통해 로드한다.
씬 fallback 데이터 Legacy/Data/GameData/GameDataCatalog.asset 즉시 수정 대상 NewRunScene.unity에 아직 fallbackCatalog로 연결돼 있다.

3. CSV 파일별 분류

파일 현재 상태 권고 분류 판단
Assets/CSVdata/source/monsters.csv 런타임 원본 유지 대상 runtime catalog의 몬스터 기본 데이터 공급원이다.
Assets/CSVdata/source/monster_skills.csv 런타임 원본 유지 대상 active/passive skill 정의와 effect prefab path를 제공한다.
Assets/CSVdata/source/monster_skill_choices.csv 런타임 원본 통합 대상 choice 메타데이터는 쓰지만, reward/modifier CSV와 분리돼 관리 비용이 높다.
Assets/CSVdata/source/monster_reward_choices.csv 런타임 원본 통합 대상 Offering 후보와 누적 보너스를 갖지만 choice 구조가 분산돼 있다.
Assets/CSVdata/source/stage_one_enemies.csv 런타임 원본 유지 대상 적 기본 능력치와 stage_one_skill 키를 제공한다.
Assets/CSVdata/EnemySkillData.csv 런타임 원본 즉시 수정 대상 현재는 일부 컬럼만 실제 적용되고, effect prefab path는 실행부에 연결되지 않는다.
Assets/CSVdata/StageDay.csv 런타임 원본 유지 대상 새 런 흐름에 직접 연결된 stage table이다.
Assets/CSVdata/StageEncounter.csv 런타임 원본 유지 대상 새 런 흐름에 직접 연결된 encounter table이다.
Assets/CSVdata/StageReward.csv 런타임 원본 유지 대상 새 런 흐름에 직접 연결된 reward table이다.
Assets/CSVdata/SkillChoiceModifierData.csv 런타임 원본 즉시 수정 대상 현재 parser가 읽지 않는 range_multiplier, range_bonus 컬럼이 남아 있다.
Assets/CSVdata/MonsterStat.csv 현행 런타임 직접 참조 없음 통합 대상 미래 source-of-truth 후보이지만, 지금은 active runtime 입력으로 연결돼 있지 않다.
Assets/CSVdata/SkillData.csv 현행 런타임 직접 참조 없음 통합 대상 현재 runtime은 이 파일 대신 monster_skills.csv를 사용한다.
Assets/CSVdata/EnemyStat.csv 현행 런타임 직접 참조 없음 통합 대상 현재 runtime은 이 파일 대신 stage_one_enemies.csv를 사용한다.
Assets/CSVdata/SkillChoiceData.csv 현행 런타임 직접 참조 없음 통합 대상 현재 runtime choice 연결은 monster_skill_choices.csv 기반이다.

5. 하드코딩된 부분

5-1. 데이터 적용 이전 또는 브리지 단계

  • 몬스터 prefab 선택이 ResolveMonsterPrefab(...)의 ID 비교 체인에 고정돼 있다.
  • 적 prefab 선택이 ResolveEnemyPrefab(...)의 ID 비교 체인에 고정돼 있다.
  • 씬 구조 루트 이름 RunTimeObject, RunTimeEnemy, RunTimeMonster와 spawn point 이름이 코드 문자열에 고정돼 있다.
  • Offering 최대 개수 3, 최대 active/passive 보유 수 5가 상수다.

5-2. 몬스터 스킬 실행 단계

  • Targeting.Range = 0f로 source skill range를 무시한다.
  • Ariel-A는 projectile speed 17f, pierce 1을 코드에서 별도로 준다.
  • projectile lifetime은 CSV value 대신 전장 폭 기반 계산식으로 다시 정한다.

5-3. 적 스킬 실행 단계

  • 적 skill prefab은 CSV path가 아니라 ResolveEnemySkillPrefab(...) switch로 정한다.
  • ShurikenThrow, AimedShot, SacredSwordWave의 projectile speed/lifetime이 상수다.
  • ChargeCommand의 이동속도/공격력 배율이 1.2f, 1.15f 상수다.
  • StageOneEnemyPassiveStatApplier도 skill kind 기준의 패시브 배율을 코드에 고정한다.

6. 불필요하거나 정리 대상인 코드

대상 현재 판단 분류
MonsterStat.csv, SkillData.csv, EnemyStat.csv, SkillChoiceData.csv를 전제한 과거 전환 문맥 현재 NewRunScene 런타임 직접 입력이 아니라 혼선만 준다. 통합 대상
SkillChoiceModifierData.csv의 range_multiplier, range_bonus 현재 parser/applier와 개념 모델에서 죽은 컬럼이다. 삭제 대상
UnitFactory.TryCreatePhase2ATestModels(...) 실제 런 경로 핵심이 아닌 테스트성 helper로 보인다. 삭제 대상
MonsterDefinition의 prototype combat 필드 일부 현재 skill-based runtime와 중복되는 필드가 있다. 즉시 삭제보다 schema 정리 후 통합이 맞다. 통합 대상

7. 즉시 수정 대상 상세

  1. fallback catalog 제거 또는 교체
    현재 NewRunScene이 여전히 Legacy/Data/GameData/GameDataCatalog.asset를 참조한다. 먼저 이 참조를 제거하거나 새 Scripts2-owned asset으로 교체해야 한다.
  2. EnemySkillData prefab path를 실제 실행에 연결
    EnemyDefinition 또는 별도 enemy skill runtime 정의에 prefab reference를 실어 ResolveEnemySkillPrefab(...) switch를 제거해야 한다.
  3. 적 하드코딩 수치를 CSV로 올리기
    projectile speed, lifetime, charge buff multiplier, passive multiplier를 명시 컬럼으로 이동해야 한다.
  4. Ariel-A 특례 제거
    projectile speed와 pierce를 skill CSV에 정식 필드로 올리고 mapper 특례를 제거해야 한다.
  5. CSV auto-sync 감시 범위 확대
    루트 EnemySkillData.csv와 필요한 루트 CSV를 postprocessor 감시 범위에 포함해야 한다.

8. 통합 대상 상세

  1. CSV source-of-truth를 하나로 정하기
    현 구조를 유지할지, 루트 MonsterStat.csv/SkillData.csv/EnemyStat.csv/SkillChoiceData.csv로 승격할지 먼저 결정해야 한다.
  2. 선택지 구조 단일화
    현재는 reward candidate, choice metadata, choice modifier가 셋으로 갈라져 있다. 최소한 공통 행 키를 가진 단일 schema 또는 명확한 2단 구조로 줄여야 한다.
  3. prototype 필드와 skill definition 필드 정리
    MonsterDefinition 내부 중복 전투 필드를 어떤 계층이 최종 권위를 갖는지 명확히 정리해야 한다.

9. 삭제 대상 상세

  1. range_multiplier, range_bonus 컬럼
    현재 range 개념을 사용하지 않고, 코드도 이 값을 소비하지 않는다.
  2. 불필요한 test helper
    TryCreatePhase2ATestModels(...)가 더 이상 유지가치가 없으면 제거 후보로 보는 것이 맞다.
  3. 통합 완료 후 비활성 루트 CSV
    루트 MonsterStat.csv 계열을 실제 원본으로 승격하지 않을 경우, 최종 구조 정리 후 삭제 후보가 된다. 지금 즉시 삭제는 아니다.

10. 권장 작업 순서

순서 작업 기대 효과
1 fallbackCatalog 제거 또는 교체 새 흐름을 CSV/runtime catalog 기준으로 단일화할 수 있다.

5 죽은 컬럼과 helper 정리 유지보수 비용과 오해를 줄인다.
