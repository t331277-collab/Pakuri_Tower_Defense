한 줄 결론

Pakuri의 다음 작업은 이브 단독 전투 프로토타입을 일반화해서, 몬스터 선택 → Run 시작 → 전투 → 보상 / 스킬 선택 → 다음 일차 진행 → 저장 / 불러오기 흐름을 가진 하나의 Run 프레임으로 확장하는 것이다.

초기 구현은 아리엘, 이브, 세인, 베가, 린 5몬스터를 대상으로 한다. 정적 게임 데이터는 CSV를 런타임에서 직접 읽지 않고 Unity 프로젝트 안의 정적 자산으로 작성해 부팅 시 1회 로드하며, 저장은 메타 저장과 런 저장을 분리한다.

최종적으로 이렇게 된다

1. 부팅 게임 시작 시 GameDataCatalog를 1회 로드한다. 그 다음 MetaSaveData와 진행 중인 RunSnapshot를 확인한다.
2. 몬스터 선택 아리엘 / 이브 / 세인 / 베가 / 린 중 1명을 선택한다.
3. Run 진행 일차별로 전투, 상점, 이벤트, 보상, 스킬 선택이 반복된다. 이 흐름은 RunSession이 중심에서 관리한다.
4. 전투와 성장 공통 전투 코어 위에서 각 몬스터의 A 스킬과 이후 A/F, B/G 축 성장 루프가 동작한다.
5. 저장 / 복귀 메타 성장과 런 진행은 분리 저장된다. 런은 전투 도중이 아니라 일차 경계 체크포인트 기준으로 복귀한다.

현재 실제 상태

  • 코드 현재 게임 전용 스크립트는 실제로 DamageCalculator.cs, EveVerticalSliceController.cs 중심이다.
  • 씬 현재 구현은 이브 단독 전투 프로토타입과 임시 HUD 수준이다.
  • UI 실제 .uxml, .uss 파일은 아직 없다.
  • 데이터 자산 실제 Assets/Resources, Assets/StreamingAssets, Assets/DataGenerated는 아직 없다.
  • 정적 데이터 코드 실제 ScriptableObject, CreateAssetMenu, GameDataCatalog 관련 스크립트는 아직 확인되지 않는다.
  • CSV 데이터 원본은 Pakuri/data에 있지만, 현재 런타임 로더는 없고 직접 로드 대상으로도 고정되지 않았다.

현재 바로 구현되지 않은 것

  • 부족 5몬스터 공통 전투 코어
  • 부족 몬스터 선택 UI / 보상 UI / Run HUD
  • 부족 RunSession, RunFlowController, SaveLoadService
  • 부족 Unity 프로젝트 내부 정적 데이터 자산 구조와 GameDataCatalog
  • 부족 5몬스터의 A 스킬 전체 구현

초기 플레이 가능 범위

  • 범위 5몬스터 선택 가능
  • 범위 각 몬스터 A 스킬 사용 가능
  • 범위 A/F 축 최소 보상 / 스킬선택 루프 동작
  • 범위 현재 구현된 항목만 3개 이하 후보로 노출
  • 제외 전투 도중 저장

권장 구현 순서

  1. 정적 데이터 자산 구조를 먼저 고정한다. 기존 Pakuri/data CSV는 참고 자료로만 두고, 런타임에서 쓸 데이터는 Unity 프로젝트 안의 정적 자산으로 만든다.
  2. RunSession, RunFlowController를 만들어 현재 이브 전용 흐름을 런 구조로 분리한다.
  3. UI Toolkit 기반의 선택 패널, HUD, 보상 패널 뼈대를 만든다.
  4. 공통 전투 코어를 만든 뒤 이브 전투를 그 위로 이관한다.
  5. 아리엘, 이브, 세인, 베가, 린의 기본 A 스킬을 붙여 첫 플레이 가능 마일스톤을 만든다.
  6. 바로 이어서 A/F 축 최소 보상 / 스킬선택을 같은 마일스톤 안에 붙인다. 이 단계에서는 골드 / 어둠의 흔적 / 포로 표시와 현재 구현된 후보만 3개 이하로 보여주면 된다.
  7. 그 다음 유물 3택1, 신규 액티브 / 신규 패시브 / 특성 / 마스터 전체 풀, B/G, C/H, D/I, E/J 순으로 확장한다.
  8. 저장은 `MetaSaveData`와 `RunSnapshot`을 나눠 체크포인트 저장으로 시작한다.

보상 / 스킬선택은 이렇게 붙인다

  • 원칙 구조를 먼저 세우고, 보상 / 스킬선택은 완전히 나중으로 미루지 않는다.
  • 첫 범위 첫 플레이 가능 마일스톤에는 A/F 축 최소 보상 루프를 같이 넣는다.
  • 첫 범위 이 단계에서는 골드, 어둠의 흔적, 포로 요약 표시와 구현된 후보 3개 이하만 노출한다.
  • 제한 런타임 효과가 아직 없는 스킬 / 보상은 선택지에 올리지 않는다.

현재 코드가 이브 전용 고정 선택지 3개만 갖고 있고, 문서 쪽은 전체 규칙이 이미 더 넓게 정의돼 있으므로, 첫 마일스톤에서는 최소 범위를 같이 붙이고 전체 선택지 풀은 후속 단계로 넘기는 방식이 가장 안전하다.

보상 / 스킬선택 중 추후 구현 예정

  • 추후 구현 예정 유물 3택1 실제 적용
  • 추후 구현 예정 신규 액티브 / 신규 패시브 / 특성 / 마스터 전체 혼합 풀
  • 추후 구현 예정 B/G, C/H, D/I, E/J 확장 선택지
  • 추후 구현 예정 전투 종류 / 스테이지 배율까지 반영한 전체 보상 계산

데이터는 이렇게 다룬다

  • 지금 확정 런타임 기준 데이터는 Unity 프로젝트 안의 정적 자산이다.
  • 지금 확정 게임은 CSV를 직접 파싱하지 않는다.
  • 지금 확정 GameDataCatalog 같은 카탈로그 자산이 정적 데이터 묶음을 참조한다.
  • 지금 확정 게임은 부팅 시 정적 자산을 1회 로드한다.

현재 CSV에는 일부 스킬 참조 불일치가 있어 이를 런타임 진실원본으로 두기보다, Unity 프로젝트 안의 정적 자산을 기준 데이터로 두고 CSV는 참고 / 이관 자료로만 다루는 구조가 더 안전하다.

데이터 중 추후 구현 예정

  • 추후 구현 예정 실제 GameDataCatalog 자산과 정적 데이터 스키마 작성
  • 추후 구현 예정 캐릭터 / 스킬 / 웨이브 / 상태이상 정적 자산 세트 작성
  • 추후 구현 예정 기존 CSV 중 필요한 항목만 선별 이관
  • 추후 구현 예정 현재 적용 시 이른 레거시 데이터 정리

특히 towers.csv, tower_skills.csv, 구형 waves.csv, 비활성 spawn_points.csv는 지금 바로 런타임 연결하기보다 정리 후 필요한 것만 자산화하는 것이 맞다.

저장 구조는 이렇게 간다

  • MetaSaveData 영구 메타 성장만 저장
  • RunSnapshot 진행 중 Run 체크포인트만 저장
  • 비저장 런타임 투사체 위치, 전투 중간 프레임 상태는 저장하지 않음
  • 복귀 기준 일차 경계 / 안전 패널 기준 복귀

저장 쪽 추후 구현 예정

  • 추후 구현 예정 실제 SaveLoadService 코드
  • 추후 구현 예정 다중 슬롯
  • 추후 구현 예정 전투 도중 저장
  • 추후 구현 예정 미작성 메타 문서 기반 해금 / 난이도 / 시작 보너스 저장

문서가 아직 부족한 부분

  • 문서 부족 메타의 캐릭터 해금, 난이도 해금, 시작 보너스 문서가 아직 없다.
  • 문서 부족 정적 데이터 정규화 기준과 Unity 자산 작성 규칙 문서는 아직 없다.

그래서 이렇게 처리한다

  • 지금 반영 린은 5몬스터 구현 범위에 포함한다.
  • 추후 구현 예정 메타 해금 / 난이도 / 시작 보너스는 현재 저장 구조에 예약만 두고 나중에 붙임
  • 추후 구현 예정 정적 데이터 자산 스키마와 작성 규칙은 실제 구현 직전 별도 handoff로 고정

Code Builder가 받게 될 메시지

지금 단계에서 Builder에게 내려갈 실제 작업은 “Unity 프로젝트 내부 정적 데이터 자산 구조를 먼저 만들고, 그 위에 RunSession과 UI 뼈대를 만들고, 이후 공통 전투 코어와 5몬스터 A 스킬, 그리고 같은 마일스톤 안에서 A/F 최소 보상 / 스킬선택 루프를 붙인다”로 요약된다.

반대로, 문서가 부족한 부분과 데이터 정리가 덜 된 부분은 추후 구현 예정으로 분리한다. 즉, 지금은 무리하게 전체 기능을 한 번에 닫는 단계가 아니라, 플레이 가능한 첫 Run 프레임을 정확한 경계 위에 세우는 단계다.

최종 요약

Pakuri는 앞으로 정적 데이터 부팅 로드, 몬스터 선택 기반 Run 흐름, 공통 전투 코어, 메타 저장 / 런 저장 분리 구조로 확장된다. 현재 구현과 문서가 충분한 영역부터 먼저 연결하고, 문서가 부족한 부분과 아직 적용 시 이른 데이터는 명시적으로 추후 구현 예정으로 남기는 방향이 맞다.
