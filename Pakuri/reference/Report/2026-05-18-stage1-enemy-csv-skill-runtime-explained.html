Stage1 Enemy CSV Skill Runtime Explained

이 문서는 2026-05-18 기준으로 Stage1 Enemy 스킬이 현재 어떤 CSV와 어떤 코드 경로를 통해 인게임에서 동작하는지 설명한다.

설명 대상은 새로 추가된 basic_skill 과 기존 stage_one_skill 의 2슬롯 구조, 그리고 scene-owned EffectManager 를 통한 enemy skill effect prefab 연결이다.

1. 한 줄 결론

현재 Stage1 Enemy 스킬 구조는 다음처럼 나뉜다.

  • stage_one_enemies.csv 가 각 적이 어떤 basic skill 과 어떤 special skill 을 가지는지 결정한다.
  • EnemySkillData.csv 가 각 skill id 의 runtime kind, 계수, 쿨다운, 반경, 투사체 속도/수명 같은 수치를 공급한다.
  • EffectManager 가 각 enemy id 와 skill kind 조합의 effect prefab 을 scene 에서 직접 연결한다.
  • EnemyCombatSimulationSystem 이 support special, offensive special, offensive basic 중 어떤 것을 언제 쓸지 결정한다.

2. 입력층 역할 분리

입력층 현재 책임 근거
Assets/CSVdata/source/stage_one_enemies.csv enemy id, attack type, 기본 스탯, stage_one_skill, basic_skill, passive text 헤더와 각 row가 실제로 basic_skill 을 포함한다.
Assets/CSVdata/EnemySkillData.csv skill id 별 runtime kind, coefficient, radius, cooldown, projectile_speed, projectile_lifetime, buff multiplier Slash, AimedShot, ShurikenThrow, Heal, GuardianFlag, ChargeCommand, SacredSwordWave row가 존재한다.
Assets/Scenes/NewScene/NewRunScene.unity 의 EffectManager enemy별 skill effect prefab authoring Unity-MCP로 현재 enemy skill effect group을 직접 읽어 확인했다.

5. 런타임 흐름

stage_one_enemies.csv -> PakuriCsvRuntimeData.ParseEnemyRow(...) -> basic_skill / stage_one_skill 분리 저장 -> ApplyEnemySkillAssignment(...) -> EnemyDefinition -> UnitFactory.CreateEnemy(...) -> EnemyUnitRuntimeModel -> EnemyCombatSimulationSystem -> EffectManager.ResolveEnemySkillEffectPrefab(enemyId, skillKind) -> 실제 이펙트 prefab instantiate

6. 코드가 실제로 어떻게 해석하는가

6-1. CSV 파싱

PakuriCsvRuntimeData.EnemyDataset.cs 는 basic_skill 을 optional enum 으로 읽는다.

  • TryReadOptionalStageOneSkill(record, "basic_skill", ...) 호출이 있고, 값이 있으면 row.HasBasicSkill = true 로 표기한다.
  • 그 다음 ApplyEnemySkillAssignment(...) 를 두 번 호출해서 special payload와 basic payload를 각각 채운다.

근거: PakuriCsvRuntimeData.EnemyDataset.cs:103, :105, :137, :159, :183, :204

6-2. Definition 과 Runtime Model

EnemyDefinition 과 EnemyUnitRuntimeModel 둘 다 이제 basic skill용 필드를 따로 가진다.

  • EnemyDefinition 에는 HasBasicSkill, BasicSkill, BasicSkillName, coefficient/cooldown/radius/projectile 관련 필드가 추가되어 있다.
  • EnemyUnitRuntimeModel 에는 basic/special cooldown을 분리하기 위한 BasicSkillCooldownSeconds, ActiveSkillCooldownSeconds 가 있다.

근거: EnemyDefinition.cs:51-62, EnemyUnitRuntimeModel.cs:11-33

6-3. 기본 사거리와 기본 쿨다운

UnitFactory 는 적이 basic skill을 가지고 있고 basic과 special이 다르면, 기본 공격 리듬을 basic 기준으로 잡는다.

  • 사거리: ResolveEnemySkillAttemptRange(...) 에 authored radius가 있으면 그것을 사용하고, 없으면 attack_type fallback을 쓴다.
  • 기본 쿨다운: ResolveEnemyAttackAttemptCooldown(...) 에서 basic/special 중 실제 기본 공격으로 쓸 쪽의 cooldown을 반환한다.

근거: UnitFactory.cs:163-171, :191-198

6-4. 전투 우선순위

EnemyCombatSimulationSystem 은 현재 다음 순서로 판단한다.

  1. 먼저 special skill을 ResolveSpecialSkill(...) 로 만든다.
  2. special이 Heal, ShieldUp, GuardianFlag, ChargeCommand 같은 support skill이면, 타깃 사거리 판단 전에 쿨다운만 맞으면 먼저 시도한다.
  3. 그 다음 offensive skill 선택은 ResolvePreferredOffensiveSkill(...) 가 맡는다.
  4. special이 공격형이고 준비되어 있으면 special을 우선 사용한다.
  5. special이 support이거나 쿨다운 중이면 basic 공격형 스킬을 본다.

근거: EnemyCombatSimulationSystem.cs:98-114, :144, :534, :558, :582

6-5. 중복 스킬 처리

basic_skill == stage_one_skill 인 경우는 source CSV는 그대로 유지하지만, 런타임은 basic을 무효로 취급한다.

  • ResolveBasicSkill(...) 안에 enemyModel.BasicSkill == enemyModel.StageOneSkill 이면 기본값을 반환하는 가드가 있다.
  • 그래서 swordsman 과 archer는 authored row에는 2칸이 차 있지만 실제 전투에서는 1종류 스킬만 돈다.

근거: EnemyCombatSimulationSystem.cs:558, :560

6-6. 쿨다운 분리

기존 1스킬 구조와 달리, 지금은 basic과 special 쿨다운이 분리되어 있다.

  • EnemyCombatState 는 BasicSkillCooldownRemaining 과 SpecialSkillCooldownRemaining 을 각각 가진다.
  • tick 시에도 둘을 따로 감소시키고, 발동 시에도 slot type 기준으로 별도 세팅한다.

근거: EnemyCombatSimulationSystem.cs:688-714, :884-885

7. Effect Prefab 은 어디서 붙는가

enemy skill effect prefab은 더 이상 CSV path가 아니라 EffectManager 가 scene에서 직접 연결한다.

  • EffectManager.ResolveEnemySkillEffectPrefab(EnemyUnitRuntimeModel enemy, StageOneEnemySkillKind skillKind) 가 explicit overload로 추가되어 있다.
  • EnemyCombatSimulationSystem 은 실제 발사 중인 skillData.SkillKind 를 넘겨서 prefab을 해석한다.

근거: EffectManager.cs:84, EffectManager.cs:95, EnemyCombatSimulationSystem.cs:239, :301, :353, :819

8. 현재 구조에서 중요한 해석 포인트

  • attack_type 는 이제 “어떤 basic skill을 가져야 하는가” 를 강제하지 않는다. 실제 skill assignment authority는 CSV row의 basic_skill 값이다.
  • 그래서 Buffer 도 지금은 AimedShot basic을 가진다. 이건 코드가 Buffer라서 정한 게 아니라 CSV가 그렇게 적혀 있어서다.
  • scene effect prefab과 CSV skill assignment는 서로 다른 책임이다. 어떤 skill을 쓸지는 CSV가 결정하고, 그 skill이 어떤 prefab을 쓰는지는 scene EffectManager 가 결정한다.
  • 중복 authored pair는 허용된다. 다만 런타임은 2개로 세지 않고 1개만 쓴다.

9. 아직 알아야 할 제한

  • Codex는 Play Mode를 돌리지 않았기 때문에, 실제 체감 리듬과 발동 빈도는 사용자 검증이 남아 있다.
  • special 우선/ basic 보조 정책은 현재 코드 정책이다. 나중에 디자인이 바뀌면 ResolvePreferredOffensiveSkill(...) 쪽을 다시 조정해야 한다.
  • 현재 문서는 “지금 코드가 어떻게 동작하는가” 설명이지, “이 구조가 최종적으로 가장 좋은가” 판단 문서는 아니다.
