UI 수정 문제와 선택한 해결 방향

발생한 문제

  • UI를 직접 수정해도 게임 시작 시 스크립트가 기본값을 다시 적용해서 원래대로 돌아갔다.
  • 일부 UI는 VerticalLayoutGroup과 ContentSizeFitter 때문에 RectTransform의 Pos X / Pos Y 이동이 막혔다.
  • MainMenuScene의 화면 전환 UI가 런타임 생성/삭제 방식이면 사용자가 모든 화면을 한 번에 편집할 수 없었다.
  • RunScene 보상 버튼은 레이아웃 제거 이후 슬롯 크기와 루트 높이가 보장되지 않아 보이지 않는 문제가 생겼다.

선택한 방법

  • UI는 코드가 계속 생성/삭제하지 않고, 씬에 존재하는 authored UI를 원본으로 본다.
  • 코드는 누락된 named anchor만 보충하고, 기존 오브젝트가 있으면 참조를 캐싱하고 콜백만 바인딩한다.
  • Edit Mode에서는 모든 주요 패널을 보이게 해서 사용자가 직접 위치와 크기를 편집할 수 있게 한다.
  • Runtime에서는 같은 오브젝트를 SetActive로 전환한다.
  • 기본 UI가 필요하면 내가 먼저 씬 안에 Canvas 기반 UI를 만들고, 사용자가 직접 만든 UI가 있으면 그 UI를 수정/바인딩하는 방향으로 간다.
  • 보상 버튼은 삭제/재생성 대신 RewardButton_0~2 고정 슬롯을 재사용한다.
  • Text는 현재 프로젝트에 com.unity.ugui만 manifest에 있고, Assets 검색에서 TextMeshPro, TMP_Text, TMPro 사용 흔적이 없어 UnityEngine.UI.Text를 유지했다.

검증 결과

  • 빌드 dotnet build Pakuri\Assembly-CSharp.csproj --no-restore는 오류 0개로 통과했다.
  • 경고 빌드 경고 2개는 Unity/MCPForUnity 참조의 System.Net.Http, System.IO.Compression 버전 충돌 경고다.
  • RunScene Unity MCP 확인에서 RunCombatCanvas와 RunCombatUiController가 존재했다.
  • 보상 버튼 Unity MCP 확인에서 RewardButton_0, RewardButton_1, RewardButton_2가 active 상태이고, legacy RewardPreviewButton은 inactive 상태였다.
  • TextMeshPro Pakuri/Packages/manifest.json에는 com.unity.ugui가 있고, com.unity.textmeshpro 항목은 확인되지 않았다.
