Code Evidence Summary

현재 스킬 CSV / 런타임 구조 설명

1. 설명 요약

  • 스킬 본체는 monster_skills.csv에 만든다.
  • 특성, 추가 효과, 자동 발동은 choices / effects / triger / status CSV로 붙인다.
  • 런타임은 PakuriCsvRuntimeData가 CSV를 읽고 검증한 뒤 catalog로 만든다.
  • 전투에서는 InGameSkillDefinitionMapper.cs, SkillExecutionSystem.cs, SkillRuntimeInstance.cs, 각 executor가 실제 실행을 맡는다.
  • 기존 공용 축 안에 있으면 CSV만 수정하면 되고, 새 축이 필요하면 C# 공용 로직을 확장해야 한다.

2. 스킬을 만드는 파일 묶음

파일 역할 주로 넣는 내용
monster_skills.csv 스킬 본체 스킬 종류, 슬롯, runtime kind, 피해, 쿨다운, 탄창, 재장전, 발사 간격, 상태 부여
monster_skill_choices.csv 특성 / 마스터 / 패시브 보정 피해 배율, 탄창 증가, 재장전 시간 감소, 발사 간격 감소, 반경 증가, 치명 보정
monster_skill_effects.csv 추가 effect 버프, 디버프, 상태 부여, 추가 피해, 지속 effect
monster_skill_triger.csv 이벤트 트리거 자동 발동, triggered skill, cooldown refund, reload reduce
status_effects.csv status 정의 status id, 기본 지속 시간, 스택 수, 상태별 수치 효과

실무적으로는 스킬 본체 1줄에 필요한 만큼 choice / effect / trigger / status row를 추가하는 구조다.

3. 런타임 처리 흐름

  1. PakuriCsvRuntimeData.cs가 CSV catalog 로드 시작
  2. PakuriCsvRuntimeData.Loader.cs가 CSV를 row 단위로 읽음
  3. PakuriCsvRuntimeData.MonsterDataset.cs가 row를 typed data로 파싱
  4. PakuriCsvRuntimeData.Validation.cs가 값과 참조를 검증
  5. PakuriCsvRuntimeData.Build.cs가 GameDataCatalog 생성
  6. PakuriDataManager.cs가 runtime lookup 등록
  7. InGameSkillDefinitionMapper.cs가 SkillDefinition을 SkillData로 변환
  8. InGameCombatManager.cs가 전투 중 SkillExecutionSystem을 tick
  9. SkillExecutionSystem.cs가 snapshot 계산, 실행기 선택, cast trigger 통지
  10. SkillRuntimeInstance.cs가 쿨다운, 탄창, 재장전, 발사 간격 관리

4. 현재 공용 로직이 이미 해주는 것

정의 계층

SkillDefinition.cs가 skill, passive, choice, effect, trigger 구조를 가진다.

modifier 누적

SkillExecutionSnapshot.cs가 피해 배율, 재장전 시간 배율, 발사 간격 배율, 탄창 보정 같은 공용 modifier를 모은다.

패시브 base 보정

SkillExecutionSystem.cs가 learned passive의 base modifier를 active snapshot에 적용한다.

지속 패시브 효과

InGamePassiveEffectRuntime.cs가 learned passive effect와 apply-once effect를 처리한다.

이벤트 트리거

SkillTriggerRuntime.cs가 damage, kill, cast 이벤트를 받아 triggered skill과 환급류를 처리한다.

실행기 계층

SkillExecutionSystem.cs에는 projectile, beam, single, zone, buff, shield, passive executor가 기본 등록되어 있다.

5. 코드 수정 없이 CSV만으로 가능한 범위

  • 기존 SkillRuntimeKind 안에 들어가는 스킬
  • 기본 피해, 계수, 쿨다운, 탄창, 재장전, 발사 간격, 관통 조정
  • 기존 choice 컬럼으로 표현 가능한 특성 / 마스터 / 패시브 보정
  • 기존 effect timing과 target 규칙으로 표현 가능한 버프 / 디버프 / 추가 피해
  • 기존 trigger event와 action 조합으로 표현 가능한 자동 발동과 환급류
  • 이미 지원되는 status id를 사용하는 상태이상
요구 사항 CSV-only 메모
기존 투사체 스킬의 피해량 / 탄창 조정 가능 기존 수치 필드만 수정하면 된다.
특성으로 재장전 시간 감소 가능 reload_time_multiplier 경로 사용
특성으로 발사 간격 감소 가능 shot_interval_multiplier 경로 사용
패시브 base가 특정 active 수치 보정 가능 PassiveBase와 snapshot 적용 경로 사용
기존 이벤트 기반 자동 발동 후 재장전 감소 가능 ReloadReduce trigger 사용

6. 코드 확장이 필요한 경우

경우 무엇이 부족한가 주 수정 파일
새로운 스킬 실행 방식 기존 runtime kind와 executor로 표현 불가 SkillDefinition.cs, InGameSkillDefinitionMapper.cs, SkillExecutionSystem.cs, 새 *SkillExecutor.cs, 필요 시 SkillRuntimeInstance.cs
choice CSV에 없는 새 modifier 축 기존 컬럼으로 수치 표현 불가 PakuriCsvRuntimeData.MonsterDataset.cs, SkillDefinition.cs, PakuriCsvRuntimeData.Build.cs, SkillExecutionSnapshot.cs, SkillExecutionSystem.cs, SkillRuntimeInstance.cs 또는 executor
새 status id 또는 새 status 규칙 validator와 runtime이 새 status를 모름 StatusEffectKind.cs, StatusEffectRuntime.cs, status_effects.csv
새 trigger event 또는 새 trigger action 기존 이벤트 / 액션 종류로 표현 불가 SkillDefinition.cs, PakuriCsvRuntimeData.Validation.cs, SkillTriggerRuntime.cs, InGameCombatManager.cs
패시브가 다른 타이밍에서 active를 수정해야 함 현재 snapshot 적용 시점만으로 부족 SkillExecutionSystem.cs, SkillExecutionSnapshot.cs, SkillRuntimeInstance.cs 또는 executor

7. 빠른 판단 기준

  • 기존 SkillRuntimeKind 안에 들어가면 먼저 CSV-only 후보로 본다.
  • 기존 choice / effect / trigger 컬럼으로 표현되면 먼저 CSV-only 후보로 본다.
  • status id가 이미 StatusEffectKind.cs에 있으면 CSV-only 후보로 본다.
  • 위 세 가지 중 하나라도 아니면 공용 코드 확장을 먼저 본다.
