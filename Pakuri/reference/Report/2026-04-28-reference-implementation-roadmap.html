2. 현재 구현 정도

영역 구현 정도 현재 실제 구현 근거 파일
데이터 모델 구현됨 MonsterDefinition, EnemyDefinition, SkillDefinition, PassiveDefinition, GameDataCatalog가 있다. 몬스터/적/스킬/패시브의 런타임 참조 구조는 이미 존재한다. Assets/Scripts/Data/*.cs
기본 전투 계산 부분 구현 DamageCalculator와 EnemyAttackResolver가 속성, 방어력, 치명타 기반 피해 계산을 담당한다. 문서의 버프/디버프 전체 상태 머신은 아직 별도 시스템으로 분리되어 있지 않다. DamageCalculator.cs, EnemyAttackResolver.cs, buff-debuff.md
전투 세로 슬라이스 부분 구현 EveVerticalSliceController가 몬스터 발사, 적 스폰/이동/공격, HP 표시, 보상 선택 대기, 적 스폰 좌표 규칙을 처리한다. 이름은 Eve지만 현재는 선택 몬스터 정의를 받아 일부 수치를 적용한다. EveVerticalSliceController.cs, RunScene.unity
스폰/전장 좌표 최근 반영 전장 좌표는 좌하단 (0,0), 우상단 (31,17) 기준이며, 일반 적은 X 33과 Y 0~17, 보스는 (33,8) 기준으로 재설정됐다. stage-basic-rules.md, EveVerticalSliceController.cs, RunScene.unity
몬스터 5종 데이터 기초 데이터 있음 Assets/Data/GameData/Monsters에 ariel, eve, rin, sein, vega 자산이 있다. 각 캐릭터의 전체 A~J 스킬 동작은 문서만큼 모두 구현된 상태는 아니다. Assets/Data/GameData/Monsters/*.asset, 2.Monster/*
1스테이지 적 기초 데이터 있음 stage1-swordsman, shieldbearer, archer, rogue, priest, guardian-captain, attack-captain, hero-karin 자산이 있다. Assets/Data/GameData/Enemies/*.asset, stage-1-enemies.md
2~4스테이지 적 미구현 stage-2-enemies.md, stage-3-enemies.md, stage-4-enemies.md에는 상세 적 목록과 스탯이 있지만, 현재 Assets/Data/GameData/Enemies에는 stage1 자산만 있다. reference/5.enemy, Assets/Data/GameData/Enemies
런 세션/최소 보상 루프 부분 구현 RunSession은 선택 몬스터, 스테이지/일차, 골드, 어둠의 흔적, 포로 표시 수, 선택 보상 기록을 가진다. RunFlowController와 RunCombatUiController는 최소 보상 선택과 다음 전투 진입을 처리한다. RunSession.cs, RunFlowController.cs, RunCombatUiController.cs
메인 메뉴/원정 시작 부분 구현 MainMenuScene과 MainMenuFlowController가 있고, 몬스터 선택 후 RunScene으로 이동한다. 문서의 암시장, 심연 강화, 훈련장, 도감 등은 아직 실제 화면/기능으로 구현되지 않았다. MainMenuScene.unity, MainMenuFlowController.cs, 7.UI/*.md
포로/공양/스킬 선택지 미구현에 가까움 보상 UI에서 포로 수를 표시하고 보상 선택을 기록하는 기초는 있으나, 포로를 현현/공양/동화로 쓰는 시스템과 스킬 선택지 풀 생성 규칙은 아직 코드 구조로 분리되어 있지 않다. prisoner-choice-system.md, skill-choice-pool-rule.md, RunSession.cs
유물/상점/이벤트/정예 전투 미구현 문서는 존재하지만 Artifact, Shop, Event, Elite 전용 런타임 스크립트/자산은 확인되지 않았다. artifact-synergy-list.md, shop-system.md, event-system.md, elite-combat-system.md
메타 성장/재화 승급 미구현 어둠의 흔적 값은 RunSession에 있지만, 메타 저장, 재화 승급, 노드 해금, 초기화 UI는 아직 없다. 6.meta/*.md, RunSession.cs
포메이션 미구현 포메이션 문서는 15개 공용 슬롯과 여러 포메이션 효과를 정의하지만, 현재 Formation 전용 스크립트나 자산은 확인되지 않았다. formation/*.md

3. 구현하지 말아야 할 착각 방지

항목 판정 이유
dungeon-squad* 문서 참고 전용 사용자가 “dungeon-squad로 시작하는 .md는 참고용이고 구현할 게 아님”이라고 명시했다. 따라서 이 문서들의 구조를 그대로 구현 대상으로 잡지 않는다.
원작 위키 기반 포메이션 수치 프로젝트 해석 필요 포메이션 문서는 원작 효과를 프로젝트 좌표로 해석한다고 적고 있다. 바로 전체 수치를 구현하기보다 슬롯 데이터와 배치 선택 UI부터 만들어야 한다.
메타 성장 전체 저장 구조 선행 필요 메타 문서는 런 외부 영구 성장이다. 현재는 저장/로드 구조가 코드에 없으므로, 노드 UI보다 저장 모델과 재화 모델을 먼저 만들어야 한다.

4. 다음 구현 순서

아래 순서는 현재 코드가 이미 가진 최소 전투/런 루프를 깨지 않고, 문서 구현 범위를 작은 검증 단위로 넓히는 순서다.

순서 구현 묶음 구체 작업 선행 근거 완료 기준
1 현재 전투/런 루프 안정화 현재 EveVerticalSliceController에 몰린 전투 상태, 적 상태, 보상 상태를 큰 동작 변경 없이 작은 서비스/런타임 구조로 분리한다. 우선 public 동작은 유지하고 테스트 가능한 단위만 만든다. 전투, 보상, 적, UI가 한 컨트롤러에 집중되어 있음. 기존 RunScene 전투가 유지되고, 빌드 오류가 없으며, 보상 선택과 다음 전투 진입이 유지된다.
2 런 일차/전투 타입 모델 RunSession에 현재 일차 진행, 일반/정예/중간보스/보스 전투 타입, 상점 등장 여부를 표현하는 구조를 추가한다. 단, dungeon-squad-run-structure.md는 참고용으로만 보고, 구현 기준은 combat-reward-system.md, elite-combat-system.md, shop-system.md의 현재 프로젝트 문서로 둔다. 전투 보상 문서가 전투 종류별 포로/유물/골드/어둠의 흔적 보상을 정의함. 전투 종류에 따라 보상 수치가 달라지고, 아직 상점/이벤트가 없어도 일차 상태가 유지된다.
3 전투 보상 실제화 포로 1~3명 확률, 보스 포로 확정, 골드, 어둠의 흔적 지급을 문서 기준으로 코드화한다. 유물은 보스전 후보 구조만 먼저 만들고 효과 적용은 뒤로 미룬다. combat-reward-system.md가 포로 확률, 골드, 어둠의 흔적 지급량을 정의함. 보상 화면에 실제 포로 후보/골드/어둠의 흔적이 표시되고 RunSession에 누적된다.
4 포로 사용: 공양과 스킬 선택지 풀 포로 선택 중 먼저 공양만 구현한다. 신규 액티브, 신규 패시브, 배운 액티브의 특성, 마스터 후보를 하나의 풀로 만드는 구조를 만든다. 현현/동화/고문은 UI 버튼만 잠금 또는 미구현 표시로 둔다. prisoner-choice-system.md, skill-choice-pool-rule.md, monster-basic-rule.md. 전투 후 포로를 공양하면 3개 이하 선택지가 나오고, 선택한 보상이 중복 등장하지 않는다.
5 몬스터 A~J 스킬 데이터 정리 현재 5몬스터 자산의 스킬/패시브 데이터가 각 캐릭터 문서와 맞는지 점검하고, 최소한 A 기본 스킬과 F 기본 패시브, B~E/G~J 해금 관계를 데이터로 표현한다. 모든 복잡한 효과 구현보다 선택/해금 구조를 먼저 완성한다. 2.Monster/*-tower.md와 각 skill/*.md, monster-basic-rule.md. 각 몬스터가 A를 기본 보유하고, 선택지에서 B~E/F~J가 문서 조건대로 잠기거나 열린다.
6 상태 효과 기반 확장 감전, 추위, 빙결, 취약, 신성 방어막, 축복, 노출/저항 감소, 이름표식, 침묵 등 상태를 공통 모델로 만든다. 먼저 이브/베가/아리엘의 현재 스킬과 직접 연결되는 상태부터 구현한다. buff-debuff.md, combat-attribute-and-damage-system.md. 상태 지속시간, 스택, 피해 계산 보정이 전투 로그 또는 UI에 확인 가능하다.
7 2~4스테이지 적 데이터 stage-2, stage-3, stage-4 문서의 일반 적/중간보스/보스 데이터를 EnemyDefinition 자산으로 생성한다. 특수 패턴은 우선 텍스트/단순 수치로 들어가고, 행동 구현은 뒤따르게 한다. stage-2-enemies.md, stage-3-enemies.md, stage-4-enemies.md. GameDataCatalog에서 스테이지별 적 후보를 가져올 수 있다.
8 정예 전투와 이벤트 정예 접두 이벤트 5종을 전투 시작 보정으로 구현하고, 일반/정예 전투 진입 직후 20% 이벤트 판정을 추가한다. 이벤트 결과는 현재 전투 1회 보정과 보상 추가부터 제한적으로 적용한다. elite-combat-system.md, event-system.md, event-list.md. 일반 진행일에서 정예 선택지와 이벤트 팝업이 조건에 맞게 발생한다.
9 상점과 유물 후보 스테이지당 1회 상점, 골드 구매, 유물 후보 3택1, 이미 보유한 유물 제외를 구현한다. 유물 효과는 처음에는 스탯/피해 보정형만 적용하고 소환물/전장 오브젝트는 뒤로 둔다. shop-system.md, artifact-synergy-list.md. 상점 이용일은 전투 없이 넘어가고, 유물 후보가 중복 없이 선택된다.
10 포메이션 데이터와 시작 포메이션 선택 15개 공용 슬롯, Basic 및 각 포메이션의 5개 슬롯 매핑을 데이터화한다. 원정 시작 화면에서 난이도/몬스터/포메이션 3단계 선택을 구현한다. formation/1.Formation-Basic-Rule.md, 개별 포메이션 문서, 7.UI/3. expedition-start-layout.md. 선택한 포메이션에 따라 전투 시작 몬스터 배치 좌표가 달라진다.
11 메타 저장과 심연 강화 어둠의 흔적 보유량 저장, 10:1 승급, 캐릭터별 스탯 강화, 액티브 강화, 초기화 수수료를 구현한다. 먼저 저장 모델과 심연 강화 화면의 핵심 노드만 만든다. 6.meta/*.md, 7.UI/5. abyss-upgrade-layout.md. 런 종료 후 어둠의 흔적이 남고, 다음 런 시작 전 강화 효과가 적용된다.
12 도감/훈련장/암시장 실제 게임 루프에 필요한 데이터가 쌓인 뒤 도감, 훈련장, 암시장을 구현한다. 이들은 우선순위가 낮고, 전투/런/보상/메타가 먼저 안정되어야 한다. 7.UI/2. guidebook-popup-layout.md, 7.UI/6. training-ground-layout.md, 7.UI/7. black-market-layout.md. 도감은 실제 데이터에서 읽고, 훈련장은 전투 파라미터를 바꿔 테스트하며, 암시장은 메타 재화/상품과 연결된다.

5. 바로 다음 Builder handoff 후보

다음 구현을 바로 시작한다면 범위를 아래처럼 작게 자르는 것이 가장 안전하다.

후보 구현 범위 이번에 제외할 것
추천 1: 전투 보상 실제화 포로 수 확률, 보스 포로 확정 표시, 골드/어둠의 흔적 지급, RunSession 누적. 유물 시너지 효과, 포로 현현/동화, 상점, 메타 저장.
추천 2: 포로 공양 선택지 공양 버튼, 선택지 풀 생성, 선택 기록, 액티브/패시브 해금 조건. 모든 스킬 효과 완전 구현, 마스터 스킬 연출, 현현/동화.
추천 3: 포메이션 데이터 15개 슬롯과 Basic/돌격/방어/원소/흑백/공성/일제사격/거석 슬롯 매핑 데이터. 포메이션별 복잡한 효과 계산, 편성 화면 전체 UX.

가장 추천하는 첫 단계는 전투 보상 실제화다. 이유는 현재 코드에 이미 보상 UI와 RunSession 누적 필드가 있어서, 문서 규칙을 작은 범위로 검증하기 쉽기 때문이다.
