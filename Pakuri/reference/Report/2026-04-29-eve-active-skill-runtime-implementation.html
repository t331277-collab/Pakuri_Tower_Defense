Eve 액티브 스킬 런타임 구현 보고서

작성일: 2026-04-29 / 근거: 실제 전투 코드, Eve 스킬 문서, BLACKBOARD 검증 기록

A-E Eve 액티브 스킬 5종의 런타임 흐름을 구현했다.
Click A는 클릭 방향 수동 발사, B-E는 같은 클릭을 트리거로 조건부 자동 발동한다.
Status 감전, 추위, 빙결, 둔화, 취약, 보호막 표시를 런타임에 연결했다.
PASS 빌드와 Unity 콘솔 확인 뒤 외부 Code Reviewer가 통과 판정했다.

1. 구현 범위

이번 구현은 Eve의 액티브 스킬 A-E를 실제 전투 런타임에 연결하는 작업이었다. 기준 문서는 Pakuri/reference/2.Monster/eve/skill 아래의 a-arc-bolt.md, b-prism-ray.md, c-frost-field.md, d-static-override.md, e-drone-beacon.md이며, 실제 구현은 CombatRuntimeEveSkills.cs, CombatRuntimeProjectiles.cs, CombatRuntimeEnemies.cs, CombatRuntimeController.cs, CombatRuntimeScene.cs에 들어갔다.

최종 동작 기준은 “A는 플레이어가 클릭한 방향으로 수동 발사하고, 이 클릭이 B-E 자동 스킬의 발동 트리거가 된다”이다. 또한 B-E는 사거리 제한 없이 가장 가까운 적 또는 스킬 고유 우선순위 대상에게 발동하도록 정리했다.

2. 자세한 스킬 설명을 먼저 받은 이유

이번 작업에서 오류를 줄이는 핵심은 “스킬 이름만 보고 구현하지 않고, 사용자가 스킬별 의도와 예외를 먼저 자세히 설명한 뒤 구현했다”는 점이다. 처음에는 A-E 전체를 클릭 시 자동 타겟팅하는 흐름으로 해석할 여지가 있었지만, 이후 설명을 통해 A와 B-E의 책임이 분리됐다.

사용자 설명으로 고정된 내용 구현에 끼워 넣은 방식 근거 코드
A는 자동 시전이 아니라 클릭한 방향으로 나가는 기본 수동 스킬이다. FirePrimarySkill()이 클릭 지점에서 방향을 계산한 뒤 Eve일 때 FireManualEveArcBolt(direction)로 보낸다. CombatRuntimeProjectiles.cs의 FirePrimarySkill, CombatRuntimeEveSkills.cs의 FireManualEveArcBolt
클릭은 B-E 스킬들의 트리거 역할도 한다. UpdateSelectedMonsterCombat()이 클릭 프레임에 TryTriggerEveAutomaticSkills()를 호출하되 A 발사 흐름은 계속 진행한다. CombatRuntimeProjectiles.cs의 UpdateSelectedMonsterCombat, CombatRuntimeEveSkills.cs의 TryTriggerEveAutomaticSkills
B-E는 조건부 자동 시전과 자동 타겟팅이다. TryTriggerEveAutomaticSkills()는 B, C, D, E만 호출한다. A는 여기서 제외했다. CombatRuntimeEveSkills.cs 91번대 메서드
스킬 사거리는 무한이며, 타겟이 있으면 가장 가까운 적 또는 고유 우선순위 대상에게 발동한다. B, C, D는 FindNearestEnemy(..., float.PositiveInfinity)를 사용한다. D는 감전 대상 predicate를 유지한다. E 드론도 무한 사거리로 탐색한다. CombatRuntimeEveSkills.cs 225, 300, 389, 477, 595 라인 부근

3. 스킬별 구현 방식

스킬 런타임 구현 특성/상태 연결
A. 아크 볼트 FireManualEveArcBolt(Vector3 baseDirection)에서 클릭 방향을 기준으로 투사체를 생성한다. 추가 투사체는 각도 오프셋으로 벌려 발사하고, 관통 수는 ProjectileRuntime.RemainingPierce에 저장한다. 특성 1-4는 피해, 관통, 추가 투사체, 발사 간격, 재장전 보정에 반영했다. 특성 5는 위력 +25%와 상태 확률 +35%를 ProjectileRuntime.StatusChance에 저장한다.
B. 프리즘 레이 TryCastEvePrismRay()가 가장 가까운 적 방향으로 선형 효과를 만들고, CreateLineEffect()와 TickSkillEffect()로 지속 피해를 준다. 피해 배율, 폭, 지속시간, 틱 간격, 쿨다운 특성을 반영한다. 적중 틱에서 확률적으로 둔화 값을 적용한다.
C. 프로스트 필드 TryCastEveFrostField()가 가장 가까운 적 위치에 원형 필드를 생성한다. 필드는 TickSkillEffect()에서 범위 내 적에게 얼음 피해와 추위를 적용한다. 특성 5는 얼음 피해 +20%와 빙결 지속시간 +1.0초를 반영한다. SkillEffectRuntime.FreezeDuration이 enemy.FreezeTimer에 도달하도록 연결했다.
D. 스태틱 오버라이드 TryCastEveStaticOverride()는 전체 적 중 감전 상태인 가장 가까운 대상을 찾는다. 감전 대상이 없으면 발동하지 않는다. 대상의 감전 스택을 피해 배율에 사용한다. 특성 4는 폭발 적중 대상에게 감전을 추가하고, 특성 5는 감전 스택 조건부 피해 증폭을 적용한다.
E. 드론 비컨 TryCastEveDroneBeacon()이 Eve 뒤쪽에 드론 런타임 오브젝트를 만들고, UpdateDrones()와 FireDroneProjectile()이 주기적으로 가장 가까운 적에게 투사체를 발사한다. 드론 지속시간, 공격 주기, 피해, 비컨 수, 재장전, 취약 스택 특성을 반영한다. 드론 투사체는 SkillId = "eve-e"로 취약 적용 경로를 탄다.

4. 상태이상과 피해 처리

상태 런타임 필드는 EnemyRuntime에 들어갔다. 실제 필드는 ShockTimer, ShockStacks, ChillTimer, ChillStacks, FreezeTimer, VulnerableStacks, SlowTimer, SlowMultiplier이다.

상태 적용 경로 전투 반영
감전 ApplyShock(), A 투사체 상태 확률, D 특성 4 이동 속도 계수에 감전 스택을 반영하고, D의 우선 타겟 조건으로 사용한다.
추위 ApplyChill(), C 필드 틱 이동 속도 계수에 추위 스택을 반영하고, 파란색 상태 시각화에 포함한다.
빙결 C 특성 5의 FreezeDuration이 FreezeTimer에 적용된다. FreezeTimer가 남아 있으면 적 이동 처리를 건너뛴다.
둔화 B 광선 틱의 확률 둔화 SlowMultiplier가 적 이동 속도 계산에 들어간다.
취약 E 드론 투사체 적중 시 ApplyVulnerable() ApplyEveSkillDamage()에서 받는 피해 배율로 사용한다.

5. 화면 표시와 수동 편집 보존

스킬 구현 중 HP 바와 상태 표시도 같이 정리했다. 적 HP 바는 빨간색, 보호막 바는 흰색으로 표시된다. 사용자가 RunScene에서 직접 배치한 EveUnit 하위 MonsterHpLabel, MonsterHpBar의 Position과 Scale은 런타임 초기화로 원복되지 않도록 보존했다.

대상 보존 방식 근거 코드
MonsterHpLabel 기존 오브젝트가 있으면 localPosition과 localScale을 다시 쓰지 않는다. CombatRuntimeScene.EnsureStatusLabel()
MonsterHpBar 기존 루트, Background, Fill, Shield Transform을 보존하고 새로 생성할 때만 기본값을 넣는다. CombatRuntimeEnemies.CreateHpBar(), CreateShieldBarFill()
EveUnit 등 앵커 기존 SpriteRenderer가 있으면 앵커 Scale을 다시 쓰지 않는다. CombatRuntimeScene.EnsureSpriteRenderer()
BattlefieldBackground 위치를 강제로 중앙 복귀하지 않고, Scale은 AutoFitBattlefieldBackgroundToField가 켜진 경우에만 자동 조정한다. CombatRuntimeScene.EnsureBattlefieldBackgroundVisual()

7. 남은 주의점

  • 현재 Eve A-E는 다른 몬스터 스킬 구현의 기준 형태로 쓸 수 있지만, 아직 모든 몬스터의 복잡한 런타임 효과까지 일반화한 프레임워크는 아니다.
  • 빙결과 추위는 현재 같은 파란색 계열 시각화를 공유한다. 이 결정은 사용자가 임시로 허용한 상태이며, 나중에 별도 시각 효과가 필요할 수 있다.
  • Pakuri/Assets/Data/GameData/Monsters/eve.asset의 trailing whitespace 리뷰 지적은 별도 작업에서 사용자가 보류한 항목이므로 이번 문서와 구현에서는 수정하지 않았다.
  • 새 UI/전투 오브젝트를 추가할 때는 기존 오브젝트가 있으면 Transform을 보존하고, 새로 생성할 때만 기본 배치를 적용하는 패턴을 유지해야 한다.
