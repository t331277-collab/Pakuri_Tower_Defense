RunScene 현현 UI 및 현현 몬스터 런타임 상태 점검

작성일: 2026-05-08. 이 문서는 실제 Unity-MCP 씬 검사, 현재 C# 코드, 관련 board 기록을 근거로 작성했다.

결론

필수 패널과 버튼은 현재 로드된 RunScene에 정확한 이름으로 존재한다. 코드가 찾는 주요 이름은 RewardPanel, PrisonerChoicePanel, PrisonerSummonerPanel, PrisonerOfferingPanel, PrisonerManifestFailurePopup이다.

단, PrisonerOfferingPanel 안에 DefeatPanel 자식과 중복 Title이 남아 있다. 이것은 바인딩 실패는 아니지만 화면이 이상하게 보일 수 있는 실제 씬 구조 문제다.

현재 역할

Designer 관점의 점검 및 보고서 작성이다. 이번 요청에서는 C# 로직이나 씬 계층을 고치지 않고, 실제 상태를 HTML로 정리했다.

1. RunCombatCanvas UI 연결 점검

Unity-MCP 검사 시 활성 씬은 RunScene이며, RunCombatCanvas에는 Canvas, CanvasScaler, GraphicRaycaster, RunCombatUiController가 모두 있었다.

대상 현재 씬 검사 결과 코드 바인딩 기준 판정
RewardPanel 존재. 자식 Title, Summary, RewardButtons, ContinueButton 존재. RewardButtons/Prisoner, Artifact, Material 모두 Button과 Label 텍스트 보유. CacheUiReferences()가 RewardPanel, RewardButtons, ContinueButton을 찾고, 보상 버튼 슬롯은 EnsureRewardButtonSlots(...)로 확인한다. 연결 가능
PrisonerChoicePanel 존재. ManifestButton, AssimilateButton, OfferingButton, CorruptButton 모두 Button과 Label 텍스트 보유. EnsurePrisonerChoicePanels()에서 ManifestButton은 TryManifestPrisonerMonster에 연결된다. 연결 가능
PrisonerSummonerPanel 존재. MonsterImage, Summary, SummonButton, ContinueButton, BackButton, Title 존재. SummonButton과 ContinueButton은 현재 결과 닫기인 ClosePrisonerSummonerResult에 연결된다. 현현 성공/실패 굴림은 더 이상 SummonButton에서 하지 않는다. 연결 가능
PrisonerOfferingPanel 존재. Choice1, Choice2, Choice3 모두 Button과 Label 텍스트 보유. 그러나 자식으로 DefeatPanel이 있고, Title이 두 개다. CacheUiReferences()는 PrisonerOfferingPanel을 우선 사용하고 Choice1..3을 공양 선택 버튼으로 바인딩한다. 버튼 연결은 가능하지만 계층 정리 필요
PrisonerManifestFailurePopup 존재. Title, Summary, CloseButton 존재. CloseButton은 Button과 Label 텍스트 보유. ShowManifestFailurePopup(...)이 이 패널을 켜고, CloseButton은 ClosePrisonerManifestFailurePopup에 연결된다. 연결 가능
사용자 메시지의 오탈자 이름 PrisoneChoicePanel, PrisonerOffringPanel, ProsonerManifextFaailurePopUP는 현재 씬에 존재하지 않았다. 현재 C# 코드는 오탈자 이름을 찾지 않고 정확한 이름만 사용한다. 오탈자 패널 잔존 없음

근거: Unity-MCP execute_code 씬 검사 결과. RunCombatCanvas 직접 자식은 HudPanel, MonsterPanel, RewardPanel, PrisonerChoicePanel, PrisonerSummonerPanel, PrisonerOfferingPanel, PrisonerManifestFailurePopup, DefeatPanel이었다.

2. 지금 보이는 UI 이상 현상의 실제 구조 원인

현재 검사에서 가장 눈에 띄는 문제는 PrisonerOfferingPanel 내부에 DefeatPanel이 들어가 있는 점이다. 루트에도 별도의 RunCombatCanvas/DefeatPanel이 있으므로, Offering 패널 아래의 DefeatPanel은 의도한 바인딩 대상이 아니다.

또한 PrisonerOfferingPanel 안에 Title이 두 개 있다. RunCombatUiController는 offeringPanel.transform.Find("Title")로 첫 번째 Title만 잡기 때문에, 중복 제목은 화면 겹침이나 편집 혼동을 만들 수 있다.

근거: Unity-MCP 검사에서 PANEL_CHILD|PrisonerOfferingPanel|4|DefeatPanel, PANEL_CHILD|PrisonerOfferingPanel|3|Title, PANEL_CHILD|PrisonerOfferingPanel|5|Title가 확인됐다.

3. 현현 성공/실패 흐름의 현재 구조

단계 현재 코드 동작 근거
포로 보상 클릭 포로 보상이면 보상 버튼을 다시 그리기 전에 OpenPrisonerChoicePanel(...)로 이동한다. RunCombatUiController.cs의 포로 보상 처리와 OpenPrisonerChoicePanel.
현현 버튼 ManifestButton이 TryManifestPrisonerMonster에 연결되어 현현 후보 선정과 성공/실패 굴림을 수행한다. RunCombatUiController.cs:367, :647.
성공 PrisonerSummonerPanel을 열고, 현현 결과를 보여준 뒤 결과 닫기 버튼으로 보상 화면에 돌아온다. RunCombatUiController.cs:669-673, :734-743.
실패 PrisonerManifestFailurePopup을 열고, 닫으면 보상 화면으로 돌아온다. RunCombatUiController.cs:700-722.
SummonButton 현재는 현현 굴림이 아니라 결과 닫기 흐름에 연결되어 있다. RunCombatUiController.cs:391.

4. Eve 중복 현현과 다른 몬스터 중복 문제의 현재 상태

현재 구조는 Eve 전용으로 막는 방식이 아니다. 선택된 1P 몬스터의 MonsterId를 기준으로 후보 선정, 세션 기록, 전투 파티 구성 세 곳에서 모두 차단한다. 따라서 Eve뿐 아니라 현재 선택된 Ariel, Rin, Sein, Vega도 같은 방식으로 중복 현현이 차단된다.

  • ResolveNextManifestCandidate()는 monster.MonsterId == currentSession.SelectedMonsterId이면 후보에서 제외한다.
  • RunSession.RecordManifestedMonster(...)는 IsSelectedMonster(...)이면 기록하지 않는다.
  • CombatRuntimeParty.ConfigureManifestedMonsterParty(...)는 이미 세션에 잘못 들어간 선택 몬스터 ID도 전투 슬롯 구성에서 건너뛴다.

근거: RunCombatUiController.cs:791, RunSession.cs:321/:334, CombatRuntimeParty.cs:156.

5. 현현 몬스터 스킬이 어색했던 이유

어제부터 현현 몬스터 스킬이 이상했던 핵심 이유는, 처음 현현 몬스터가 “실제 몬스터 한 유닛이 자기 스킬 런타임을 소유하는 구조”가 아니었기 때문이다. 과거 구현은 선택된 1P 몬스터와 별도로 CombatRuntimeParty 쪽에서 현현 몬스터를 순회하며 공통 처리했고, 일부 스킬은 등록된 몬스터별 구현 대신 단순 선/빔 또는 단발 효과처럼 보이는 공통 경로를 탔다.

그 결과 A 스킬이 projectile/magazine/reload를 가져야 하는 몬스터도 빔처럼 보이거나, Offering으로 얻은 스킬이 쿨다운은 도는데 실제 스킬 종류에 맞는 효과가 아니거나, Eve Frost Field 같은 지속 스킬이 한 번만 타격하는 문제가 생겼다.

현재 수정 방향은 RunSession.RunMonsterState로 각 파티 멤버의 성장 상태를 분리하고, CombatUnitRuntime과 CombatSkillRuntime으로 2P-5P 현현 유닛이 자기 몬스터, HP/스탯, 배운 스킬, 탄창/쿨다운/재장전 상태를 소유하게 만든 것이다. 전장 오브젝트 생성, 피해 적용, projectile/effect 생성은 여전히 CombatRuntimeController 계열 서비스가 담당한다.

6. 현재 현현 런타임 구조

계층 현재 책임 실제 파일 근거
RunSession 선택 몬스터 ID, 현현 몬스터 ID 목록, 파티 멤버별 RunMonsterState, Offering 선택/학습 스킬을 보관한다. RunSession.cs: SelectedMonsterId, RecordManifestedMonster, EnsurePartyMemberState.
RunCombatUiController 보상 UI, 포로 선택, 현현 성공/실패 UI, 공양 UI를 바인딩하고 세션 변경 뒤 전투 파티를 갱신한다. RunCombatUiController.cs: EnsurePrisonerChoicePanels, TryManifestPrisonerMonster, IsRewardModalOpen.
CombatUnitRuntime 각 전투 유닛 컴포넌트가 몬스터 정의, 런 세션 상태, HP/스탯, 스킬 런타임 목록을 가진다. CombatUnitRuntime.cs: Monster, State, Skills, ConfigureManifested, ConfigureSelected.
CombatSkillRuntime 스킬별 쿨다운, 탄창 수, 재장전, 사격 간격, Vega A 예약 발사 상태를 가진다. CombatSkillRuntime.cs: CooldownRemaining, ShotsRemaining, ReloadRemaining, PendingVegaProjectileCount.
CombatRuntimeParty 현현 몬스터를 CombatRoot/2PMonster부터 5PMonster 슬롯에 연결하고, 각 유닛의 스킬 실행을 전장 서비스로 연결한다. CombatRuntimeParty.cs: manifestedMonsters, CreateCombatUnitRuntime, TickManifestedUnitSkill.
Eve 특수 경로 현현 Eve A는 자동 조준 Arc Bolt projectile 경로를 사용하고, Eve B-E는 unit runtime 기반 공유 캐스터 경로를 사용한다. CombatRuntimeEveSkills.cs: TryTickEveUnitSkill, TryFireEveUnitArcBolt, ManifestedSource.

7. Vega 이름표식 문제의 현재 상태

현재 코드는 일반 현현 projectile에는 이름표식 스택을 0으로 넘기고, projectile runtime 저장 시에도 IsManifestedVegaThreeSwordFlurry(skill)가 참일 때만 VegaNameMarkStacks를 유지한다. 따라서 비-Vega 현현 A 공격에 Vega 이름표식이 붙는 문제는 현재 코드 기준으로 차단되어 있다.

Vega A는 예외다. vega-a는 현현 상태에서도 세 검 투사체 큐를 사용하고, 그 projectile에만 이름표식을 실어 보낸다.

근거: CombatRuntimeParty.cs:554, :617, :1064, :1120-1121.

8. 남은 확인 항목

  • 씬 정리 필요: PrisonerOfferingPanel/DefeatPanel 자식과 중복 Title은 수동 정리 또는 별도 수정 요청 대상이다.
  • Play Mode 필요: 버튼 클릭 후 실제 화면 전환, 현현 성공/실패 확률, 전투 중 현현 몬스터 스킬 발동은 AGENTS.md 규칙상 사용자가 Play Mode에서 확인해야 한다.
  • 코드 기준 연결: 현재 필수 버튼 오브젝트는 모두 Button 컴포넌트와 Label 텍스트를 보유하고 있어 EnsureButton 기반 바인딩 조건을 충족한다.
