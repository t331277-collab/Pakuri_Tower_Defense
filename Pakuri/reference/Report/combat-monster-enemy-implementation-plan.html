2. 구현 방향 결론

구현은 CSV 런타임 로딩이 아니라, 문서와 필요한 CSV 스키마를 근거로 Unity ScriptableObject 정적 자산을 확장하는 방식이 맞다. 기존 흐름도 GameDataCatalog.asset와 MonsterDefinition.asset을 사용하는 방향으로 이미 잡혀 있다.

  1. 공통 전투 모델 먼저 구현: 유닛 기본 스탯, 속성별 방어력, 버프/디버프, 피해 계산을 공통 타입으로 분리한다.
  2. Stage 1 적 데이터 구현: stage-1-enemies.md의 수치를 기준으로 적 정의 자산을 만든다. CSV의 현재 적 값은 Stage 1 수치로 직접 사용하지 않고 스키마 참고만 한다.
  3. Monster 스킬 데이터 구현: 2.Monster 아래 실제 스킬 문서를 데이터화한다. A는 기본 습득, B~E/F~J는 런 중 선택 규칙을 따른다.
  4. 스킬 실행기 구현: 탄창형, 쿨타임형, 투사체, 직선, 원형, 전장, 버프, 디버프, 표식/스택 계열을 공통 실행기로 처리한다.
  5. 기존 프로토타입 교체: EveVerticalSliceController에 붙어 있는 단일 적/단일 스킬 로직을 새 전투 런타임에 연결한다.

4. 전투 계산 구현 방식

4.1 속성별 방어력 계산

현재 DamageCalculator.Resolve는 방어력 숫자 하나만 받는다. 다음 구현에서는 공격의 DamageAttribute와 대상의 AttributeDefenseSet을 받아 대응 방어력을 고른 뒤, 문서 순서대로 고정 증가, 고정 감소, 퍼센트 증가, 퍼센트 감소를 적용한다.

단계 처리 근거
1 공격 속성에 해당하는 기본 방어력 선택 각 공격은 동일 속성 방어력만 참조한다는 전투 속성 문서
2 BaseDef + FlatBonus - FlatReduction 고정 증감이 퍼센트보다 먼저 적용된다는 문서
3 * (1 + PercentBonus) 퍼센트 증가는 고정 증감 이후 곱연산
4 * (1 - PercentReduction_1) * ... 퍼센트 감소는 합산이 아니라 각각 곱연산
5 BaseDamage * 100 / (100 + FinalDef) 방어력은 최종 피해의 퍼센트 경감

4.2 치명타

기본 치명타 확률 5%, 치명타 피해 150%를 공통값으로 두고, 공격자 보너스와 대상 치명타 저항을 합연산한 뒤 방어력 반영 이후 치명타 배율을 적용한다. 현재 DamageCalculator의 기본값은 문서와 맞지만, 대상 치명타 저항과 취약 스택에 의한 치명타 피해 증가가 아직 빠져 있다.

4.3 최종 피해 이벤트

딜 미터기와 패시브 트리거를 위해 실제 체력에 적용된 피해량 기준 이벤트를 발행한다. 초과 피해는 집계하지 않는다는 realtime-damage-meter.md 규칙을 따른다.

5. Stage 1 적 구현 범위

1차 구현은 stage-1-enemies.md에 있는 8종만 만든다. 다른 스테이지 문서는 이번 구현 범위에서 제외한다.

구분 적 액티브 패시브 구현 방식
일반 검사 베기: 가까운 대상 1명, 공격력 100%, 2.0초 검술 숙련: 물리 피해 10% 증가 근접 단일 공격 AI의 기준 적
일반 방패병 방패 들기: 자신, 4초 동안 받는 피해 25% 감소, 8.0초 두꺼운 갑옷: 방어력 10% 증가 자기 버프와 피해 감소 테스트용
일반 궁수 조준 사격: 가까운 대상 1명, 공격력 150%, 5.0초 정조준: 치명타 확률 8% 증가 원거리 단발 공격 테스트용
일반 도적 수리검 투척: 가까운 대상 1명, 공격력 140%, 4.0초 날카로운 수리검: 치명타 피해 20% 증가 치명타 피해 보너스 테스트용
일반 사제 치유: 주변 적 1명, 주문력 120%, 기본 회복량 50, 6.0초 신성 집중: 치유량 15% 증가 아군 회복 AI의 최소 구현
5일차 중간보스 수호대장 수호의 깃발: 자신 중심 4m, 5초 보호막 100, 10.0초 수호 숙련: 받는 피해 12% 감소 보호막과 보스급 체력 검증
10일차 중간보스 공격대장 돌격 명령: 자신 중심 5m, 이동속도 20%, 공격력 15%, 6초, 12.0초 공격 숙련: 물리 피해 12% 증가 광역 버프 검증
보스 용사 카린 성검기: 전방 직선 8m, 공격력 220%, 9.0초 용사의 힘: 물리 피해 15% 증가 직선 범위 공격과 보스전 검증

enemy-stage-index.md는 Stage 1 중간보스를 검호 레온 / 기사단장 브란으로 적고, stage-1-enemies.md는 수호대장 / 공격대장으로 적는다. 실제 구현 수치가 있는 문서는 stage-1-enemies.md이므로 1차 구현은 수호대장 / 공격대장을 기준으로 한다.

6. Monster 스킬 구현 방식

Monster 스킬은 현재 MonsterDefinition의 단일 ActiveSkillName, PassiveSkillName 구조로는 담을 수 없다. 몬스터별로 액티브 5개, 패시브 5개, 특성, 마스터 스킬을 데이터화해야 한다.

몬스터 액티브 방향 패시브 방향 1차 구현 우선순위
아리엘 신성 투사체, 방어막, 축복, 신성 노출, 전장 광역 아군 신성 피해, 방어막 효율, 축복 강화, 신성 노출 집중 피해 방어막과 신성 노출이 공통 시스템 준비 후 구현
이브 번개 투사체, 직선 광선, 얼음 장판, 감전 폭발, 설치형 드론 감전/추위/빙결/취약 대상 보너스와 아군 트리거 현재 프로토타입이 있어 A부터 공통 시스템으로 이전
린 물리 연사, 행동속도 버프, 직선 넉백, 마무리, 범위 강타 물리 피해 강화, 행동속도/공격력 강화, 처치 보상, 방어 약화 물리 방어력과 넉백 최소 구현 후 진행
세인 화염 탄창, 다연발, 지연 폭발, 화염 장판, 전장 결전기 아군 화염 피해, 화염 트리거, 화염 저항 감소, 화염 노출 화염 저항 감소/노출 시스템 후 구현
베가 관통 3연 검기, 침묵, 몰살 허가, 표식 전체 참격, 표식 처형 이름표식 대상 피해, 침묵 대상 보너스, 행동속도 강화, 쿨타임 충전 이름표식/침묵/몰살 허가 상태 시스템 후 구현

선택지 규칙

  • 전투 시작 시 액티브 A만 배운 상태로 시작한다.
  • 액티브는 최대 3개, 패시브는 최대 3개까지 배운다.
  • F 패시브는 A 대응 패시브이고, G~J는 각각 B~E를 배운 뒤 해금한다.
  • 액티브 하나당 특성 5개 중 3개를 고르면 마스터 2택1이 열린다.

7. 구현 순서

순서 작업 완료 기준
1 공통 enum/model 추가: 속성, 스킬 슬롯, 스킬 타입, 스탯, 방어력, 상태 효과 MonsterDefinition과 신규 EnemyDefinition이 공통 모델을 참조한다.
2 DamageCalculator 확장 속성별 방어력, 버프/디버프 보정, 치명타 저항, 취약을 계산할 수 있다.
3 Stage 1 적 ScriptableObject 생성 8종 적의 기본 능력치, 속성별 방어력, 액티브, 패시브가 자산으로 존재한다.
4 스킬 실행기 최소 세트 구현 탄창 투사체, 쿨타임 단발, 자기 버프, 광역 버프, 회복, 직선 범위가 동작한다.
5 이브 A 스킬을 공통 실행기로 이전 현재 프로토타입 전투가 새 데이터/계산기로 같은 흐름을 유지한다.
6 5몬스터 A~E/F~J 데이터 등록 선택지 풀에서 문서 기준 신규 액티브/패시브가 해금 조건에 맞게 나온다.
7 Stage 1 전투 편성 연결 일반일, 5일차, 10일차, 11일차가 Stage 1 적 규칙을 사용한다.

8. 리스크와 보류 항목

  • 현재 EveVerticalSliceController는 많은 책임을 한 클래스에 갖고 있어, 전체 스킬/적 시스템을 그대로 넣으면 유지보수가 어려워진다. 공통 런타임으로 분리해야 한다.
  • CSV의 현재 적/스킬 값은 Stage 1 용사길드 문서와 직접 일치하지 않는다. CSV 값을 그대로 쓰면 문서와 다른 게임이 된다.
  • 속성 문서에는 방어력 최소값/상한/최소 피해 보장 여부가 후속 결정 항목으로 남아 있다. 현재 DamageCalculator는 방어력을 -95 이상으로 제한하지만, 문서에 확정된 값은 아니다.
  • 딜 미터기 UI는 전투 계산 이벤트가 생긴 뒤 붙이는 것이 맞다. 계산 이벤트 없이 UI부터 만들면 집계 기준이 흔들린다.

9. Builder Handoff

Code Builder에게 넘길 때는 아래 범위로 고정한다.

  1. 기존 파일 상태를 다시 읽고 DamageCalculator, MonsterDefinition, GameDataCatalog, EveVerticalSliceController, RunSession의 현재 구조를 확인한다.
  2. 먼저 데이터 타입과 계산기를 만든다. 이 단계에서는 UI를 건드리지 않는다.
  3. 다음으로 Stage 1 적 데이터 자산을 만든다. 적 수치는 stage-1-enemies.md를 우선한다.
  4. 이브 A 스킬을 새 전투 계산기로 이전해 현재 플레이 흐름을 깨지 않는지 확인한다.
  5. 그 뒤 5몬스터 스킬 전체를 데이터로 등록하고, 스킬 실행기 미지원 타입은 명시적으로 NotImplemented 상태로 표시한다.
  6. 로직 작업 후에는 AGENTS.md 규칙대로 Code Reviewer 단계로 넘긴다.
