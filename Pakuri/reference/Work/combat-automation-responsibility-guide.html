Pakuri 기초 전투 시스템 구현 시 자동화 가능 범위

이 문서는 current-architecture-plan.html에서 제안한 기초 전투 시스템을 실제로 착수할 때, 무엇을 제가 Unity MCP로 직접 만들 수 있고 무엇을 사용자가 직접 확인하거나 배치하는 편이 안전한지 정리한 문서다. 판단은 현재 프로젝트 파일과 현재 연결된 Unity Editor 상태를 근거로 했다.

짧은 결론

현재 연결 상태에서는 폴더 생성, C# 스크립트 생성/수정, 씬 GameObject 생성, 컴포넌트 부착, 좌표 배치, 기본 UI 배치, 테스트 실행까지는 제가 직접 자동화할 수 있다.

반대로 최종 아트 배치 감각, 스프라이트/애니메이션의 품질 판단, 손맛이 필요한 수치 튜닝, 사용자가 의도한 화면 연출의 미세 조정은 사용자가 직접 확인하거나 승인하는 편이 안전하다.

즉, “기초 전투 시스템이 돌아가는 뼈대”는 제가 만들 수 있고, “시각 완성도와 디테일한 감각 조정”은 사용자 확인이 필요하다.

현재 프로젝트 근거

  • Pakuri/reference/current-architecture-plan.html가 존재하며, 기초 전투 시스템의 vertical slice 방향을 이미 정리하고 있다.
  • manage_asset search 결과 현재 Assets에는 Scenes, Settings, 기본 URP/Input System 에셋만 있다.
  • Get-ChildItem Pakuri\Assets 출력에도 Assets/Scripts, Assets/Data, Assets/Prefabs는 아직 없다.
  • manage_scene get_hierarchy 결과 현재 씬 루트는 Main Camera, Global Light 2D뿐이다.
  • 이번 판단은 “이미 만들어진 전투 시스템을 수정”이 아니라 “거의 빈 프로젝트에서 기초 전투 시스템을 처음 세우는 작업”을 전제로 한다.

이 문서가 답하는 질문

  • 폴더와 스크립트를 내가 직접 만들어야 하는가, 아니면 Codex가 바로 만들 수 있는가
  • 씬에서 오브젝트 배치를 내가 직접 해야 하는가, 아니면 Codex가 자동으로 배치할 수 있는가
  • 자동화 가능한 영역과 사용자 수동 개입이 필요한 영역의 경계가 어디인가

자동화 가능 범위 요약표

항목 판정 왜 이렇게 판단하는가 비고
Unity 폴더 생성 제가 직접 가능 현재 세션의 Unity MCP에는 manage_asset(action="create_folder")가 있고, 현재 프로젝트가 연결되어 있다. Assets/Scripts, Assets/Data, Assets/Prefabs 같은 시작 구조 생성 가능
C# 스크립트 생성과 수정 제가 직접 가능 현재 세션의 Unity MCP에는 create_script, script_apply_edits, validate_script가 있다. 전투 컨트롤러, 유닛 런타임, 보상 로직 같은 기초 코드 작성 가능
씬에 빈 오브젝트/부모 구조 생성 제가 직접 가능 manage_gameobject(action="create")와 manage_gameobject(action="modify")가 현재 세션에서 사용 가능하다. CombatRoot, SpawnRoot, UIRoot 같은 계층 생성 가능
씬 좌표 배치 제가 직접 가능 GameObject 생성/수정 시 위치, 회전, 스케일 지정이 가능하다. 예: 넥서스 좌측, 적 스폰 우측, 전장 기준 좌표 배치
스크립트 컴포넌트 부착 제가 직접 가능 manage_components와 components_to_add 기반 부착 흐름을 사용할 수 있다. 스크립트 컴파일 완료 후 자동 부착 가능
기본 테스트 실행 제가 직접 가능 현재 세션에서 실제로 run_tests EditMode 호출이 성공했다. 기초 전투 로직 검증용 EditMode 테스트 실행 가능
전투용 임시 UI 배치 자동화 가능, 시각 확인 권장 UI 관련 도구는 있으나, 최종 화면 구성과 가독성은 시각 검토가 필요하다. 숫자 HUD, 승리 패널, 공양 선택 패널의 첫 버전은 자동 생성 가능
아트 자산 기반 배치 자동화 가능, 자산 전제 필요 현재 프로젝트에는 전투용 스프라이트, 프리팹, 애니메이션 자산이 아직 없다. 자산이 들어오면 배치 자동화 가능, 없으면 플레이스홀더 중심으로 진행
최종 화면 미세 조정 사용자 확인 권장 카메라 구도, 간격, 시인성, 타격감은 문서만으로 정답이 고정되지 않는다. 제가 초안 배치 후 사용자가 눈으로 확인하는 방식이 가장 안전하다
밸런스 수치 확정 사용자 결정 권장 현재 문서에는 구조는 있으나, 최종 재미를 보장하는 수치는 실제 플레이 감각이 필요하다. 초기값은 제가 넣을 수 있지만 최종값은 플레이 확인이 필요

제가 바로 자동으로 만들 수 있는 것

1. 프로젝트 폴더 골격

현재 Assets에는 게임 전용 구조가 없으므로, 저는 전투 시스템 시작용으로 Assets/Scripts, Assets/Data, Assets/Prefabs, Assets/UI 같은 폴더를 바로 생성할 수 있다.

2. 기초 전투 코드

CombatController, UnitRuntime, EnemyRuntime, NexusRuntime, DamageCalculator, RewardResolver 같은 C# 스크립트를 생성하고 연결할 수 있다.

3. 씬의 런타임 뼈대

현재 씬이 사실상 빈 상태이므로, 저는 CombatRoot, AlliesRoot, EnemiesRoot, Nexus, EnemySpawnPoint, BattleUI 같은 오브젝트를 생성해 초기 좌표까지 넣을 수 있다.

4. 기초 검증

생성 후에는 콘솔 에러 확인, 스크립트 검증, EditMode 테스트 실행까지 제가 이어서 할 수 있다.

따라서

폴더와 스크립트를 사용자가 직접 먼저 만들 필요는 없다.

현재 연결 상태가 유지된다면 제가 처음부터 직접 생성할 수 있다.

제가 자동화할 수 있지만 사용자 확인이 필요한 것

  • 전장 좌표와 카메라 프레이밍의 첫 배치
  • 전투 HUD 위치와 크기
  • 승리 패널과 공양 선택 패널의 시각 배치
  • 플레이스홀더 오브젝트 크기와 간격
  • 기본 전투 수치의 시작값

이 항목들은 제가 자동으로 넣을 수는 있지만, 최종 만족도는 사용자가 Unity 씬이나 Game View를 눈으로 보는 확인 단계가 필요하다.

사용자가 직접 하는 편이 안전한 것

  • 최종 스프라이트, 애니메이션, VFX, 사운드 선택
  • 아트 방향에 맞춘 미세한 화면 구성
  • “재미있다/손맛이 좋다” 수준의 최종 밸런스 승인
  • 문서에 아직 없는 연출 요구 추가 결정

저는 placeholder 기반 초안을 빠르게 만들 수 있지만, 최종 표현 판단은 현재 레퍼런스만으로 고정할 수 없다.

씬 배치는 누가 해야 하는가

질문 답변 근거
전투용 오브젝트를 씬에 내가 직접 배치해야 하나? 아니다. 첫 배치는 제가 자동으로 할 수 있다. 현재 세션에서 Unity 씬 조회가 가능하고, 사용 가능한 도구에 GameObject 생성/수정 기능이 있다.
배치 좌표를 내가 하나씩 손으로 넣어야 하나? 아니다. 좌표 기준이 정해지면 제가 자동으로 넣을 수 있다. current-architecture-plan.html은 좌측 넥서스, 우측 적 스폰 같은 전장 기준을 이미 제안한다.
그럼 사용자는 씬 작업을 전혀 안 해도 되나? 초기 구현은 가능하지만, 시각 품질 검토와 취향 조정에는 참여하는 편이 좋다. 현재 프로젝트에는 전투 자산이 없어, 초기 배치는 placeholder 성격이 강하다.

기초 전투 시스템 착수 시 권장 분업 방식

1. 구조 생성 제가 폴더, 스크립트, 씬 루트 오브젝트를 생성한다.
2. 기초 전투 연결 제가 넥서스, 적 스폰, 이브 공격, 적 이동, 승리 판정을 붙인다.
3. 1차 시각 확인 사용자가 씬/게임 화면을 보고 배치와 가독성을 확인한다.
4. 미세 조정 피드백을 받아 제가 좌표, UI, 수치를 다시 조정한다.

지금 바로 제가 만들게 될 가능성이 높은 경로

Assets/Scripts/Combat/CombatController.cs
Assets/Scripts/Combat/UnitRuntime.cs
Assets/Scripts/Combat/DamageCalculator.cs
Assets/Scripts/Run/RunBootstrap.cs
Assets/Scripts/Rewards/RewardResolver.cs
Assets/Scripts/UI/CombatHudController.cs
Assets/Data
Assets/Prefabs

위 경로들은 현재 존재하는 파일이 아니라, 기존 아키텍처 문서와 현재 빈 프로젝트 상태를 보고 “실제 구현을 시작하면 제가 생성할 가능성이 높은 시작 경로”를 정리한 것이다.

실제로 없는 것

  • 현재 Assets/Scripts 폴더는 없다.
  • 현재 전투용 프리팹은 없다.
  • 현재 전투용 스프라이트/애니메이션 자산은 없다.
  • 현재 씬에는 전투 관련 오브젝트가 없다.

따라서 “내가 먼저 만들어둬야 하나?”라는 질문에는 아니오가 맞다. 현재 상태는 오히려 제가 처음부터 생성하는 쪽이 자연스럽다.

최종 판단

폴더와 스크립트는 제가 직접 만들 수 있다. 사용자가 Unity Editor에서 미리 생성해둘 필요는 없다.

씬의 기본 배치도 제가 자동으로 할 수 있다. 넥서스, 적 스폰, 전투 루트, HUD 기본 위치까지는 자동화 대상이다.

다만 최종 미감과 밸런스 승인 단계는 사용자가 직접 보는 편이 안전하다. 가장 현실적인 협업 방식은 제가 뼈대를 자동 생성하고, 사용자가 화면을 보고 피드백을 주면 제가 다시 조정하는 방식이다.
