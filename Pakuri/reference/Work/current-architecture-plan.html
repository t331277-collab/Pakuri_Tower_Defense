Pakuri 프로토타입 아키텍처 시작안

현재 워크스페이스의 Reference 문서와 Unity 프로젝트 상태를 근거로 정리한 첫 구현 방향이다. 핵심 목표는 전체 기능을 한 번에 구현하는 것이 아니라, 1스테이지 1일차 전투 1회와 전투 후 포로/공양 선택 1회를 닫힌 루프로 먼저 검증하는 것이다.

작성 기준: 2026-04-23 프로젝트: C:\TowerDefence_Pakuri\Test\Pakuri Unity: 6000.3.4f1 현재 씬: Assets/Scenes/SampleScene.unity

결론

첫 시작점은 전투 씬 기초 + 최소 전투 계산 + 이브 기본 공격 + 일반 적 1종 + 전투 후 포로 공양이다. 이 조합이 가장 작은 단위로 문서의 핵심 루프를 검증한다.

1. 전장 넥서스는 좌측, 적은 우측에서 진입한다.
2. 전투 이브가 기본 스킬로 적을 공격한다.
3. 승리 일반 전투 보상으로 포로와 재화를 받는다.
4. 공양 포로를 써서 3개 강화 후보 중 1개를 고른다.
5. 다음 일차 강화 결과가 다음 전투에 반영된다.

현재 프로젝트 근거

  • Unity MCP의 manage_scene get_active 결과, 활성 씬은 SampleScene이고 경로는 Assets/Scenes/SampleScene.unity다.
  • 현재 씬의 루트 오브젝트는 Main Camera, Global Light 2D뿐이다.
  • Assets 검색 결과는 기본 URP/씬/입력 에셋 위주이며, 게임 전용 스크립트 구조는 아직 없다.
  • reference 폴더에는 전투, 런, 몬스터, 적, 보상, 메타 관련 문서가 존재한다.

먼저 정리할 충돌

콘텐츠 카탈로그에는 몬스터 목록이 바포메트, 비홀더, 케르베로스, 키메라로 적혀 있다. 하지만 실제 Reference의 몬스터 문서는 ariel, eve, rin, sein, vega가 존재한다.

첫 구현은 현재 문서가 더 구체적인 이브를 기준으로 시작하고, 이름/캐릭터 카탈로그 정리는 별도 결정 항목으로 두는 편이 안전하다.

권장 아키텍처 레이어

1. Content Data Layer

몬스터, 스킬, 적, 전투 보상, 런 구조 같은 정적 데이터를 보관한다.

MonsterDefinition SkillDefinition EnemyDefinition RewardTable StageDayTable

처음에는 코드 상수나 ScriptableObject 중 하나로 시작할 수 있다. 단, Reference 문서의 수치가 자주 바뀔 수 있으므로 전투 로직에 숫자를 직접 박아 넣지 않는 쪽이 좋다.

2. Run Flow Layer

스테이지, 일차, 전투 종류, 보상 화면 전환을 관리한다.

RunState StageState DayState EncounterResolver

첫 vertical slice에서는 stage=1, day=1, normal combat만 고정해도 된다. 이후 2~4일 상점/이벤트 확률, 5일/10일 중간보스, 11일 보스전으로 확장한다.

3. Combat Layer

전투 씬의 런타임 오브젝트, 좌표, 타겟팅, 스킬 발동, 피해 계산을 담당한다.

CombatController NexusRuntime UnitRuntime SkillRuntime DamageCalculator

첫 단계는 생명력, 공격력/주문력, 속성, 방어력, 피해 공식만 사용한다. 치명타, 상태이상, 행동속도, 탄창, 재장전은 구조만 열어두고 후순위로 둔다.

4. Reward and Growth Layer

전투 후 포로, 골드, 어둠의 흔적, 유물 후보, 공양/현현/동화 선택을 처리한다.

RewardResolver PrisonerReward SacrificeChoiceGenerator MonsterGrowthState

첫 구현에서는 공양만 지원한다. 포로를 얻고, 기존 이브에게 강화 후보 3개 중 1개를 적용하는 흐름을 먼저 닫는다.

5. Presentation Layer

전투 HUD, 보상 화면, 공양 선택 화면, 다음 일차 진입 버튼을 담당한다.

CombatHUD RewardPanel SacrificeChoicePanel RunProgressPanel

전투 중 플레이어 조작은 Reference 기준으로 공격 지점 지정이 핵심이다. 첫 버전은 입력 지점으로 이브의 기본 공격 방향을 지정하는 정도면 충분하다.

완료 판정

  • 전투 시작 시 넥서스, 이브, 적 스폰이 보인다.
  • 적이 우측에서 넥서스로 전진한다.
  • 이브가 적을 공격해 처치할 수 있다.
  • 전투 종료 후 포로/재화 보상이 표시된다.
  • 공양 선택으로 이브의 수치가 변한다.
  • 다음 일차로 넘어갈 수 있다.

구현 순서

  1. 전투 씬 좌표 기준과 카메라 기준을 고정한다.
  2. 런타임 유닛과 넥서스의 최소 체력 모델을 만든다.
  3. 피해 계산기를 문서 공식대로 독립 구현한다.
  4. 이브 기본 공격과 적 이동/피격/사망을 연결한다.
  5. 전투 승리 조건과 보상 생성기를 붙인다.
  6. 공양 선택 UI와 성장 상태 반영을 붙인다.
  7. 같은 구조로 2일차 일반 전투를 반복 실행한다.
